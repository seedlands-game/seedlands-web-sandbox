# Seedlands 语义审阅规则

本目录只覆盖需要上下文和判断的规则。先读 `docs/repository-structure.md` 的“哪些已有自动检查”；格式、文件名、行数、已声明 import 禁止项和生成物新鲜度优先相信对应工具的精确结果，不重复人工报同一问题。

严重度由真实影响决定，下列“通常”不是自动定级器。P0 需有具体破坏路径；P1 需有具体未来风险；P2 不得阻塞。

## WORLD-01 世界确定性与编辑权威

- 检查：基础世界是否仍由 `seed + generatorVersion` 唯一确定；体素编辑是否只经 `World.edit()` 和现有权威提交链；渲染是否保持 Chunk Mesh 而非逐体素 Entity。
- 语义风险：间接写入、隐藏随机源、时间/平台依赖、客户端生成回退或表现层成为事实 owner，往往不由 import lint 捕获。
- 通常：导致世界分叉、存档不兼容或权威绕过为 P0。

## OWNER-01 状态与模块所有权

- 检查：Kernel 持有单一执行与状态生命周期，stdlib 拥有显式注册的机制和规则，Classic 提供内容；Web 与 Agent 只做平台适配；客户端预测、派生镜像和 UI 不反向决定权威事实。平台能力通过只读实例端口注入，不出现可重配全局。
- 语义风险：依赖方向可以合法，但职责和写入权可能已经泄漏；需沿调用和数据流判断。
- 通常：双 owner、客户端越权提交或 core 隐式平台语义为 P0；职责模糊但当前无错误路径为 P1。

## STATE-01 新鲜度、取消与重入

- 检查：异步结果在 owner 提交边界验证 epoch/revision/request identity；取消后不提交，迟到结果不覆盖新状态；重入、重试和销毁幂等且释放等待者。
- 覆盖：Worker、mesh/streaming、网络基线、持久化、资源加载、音频和 UI session。
- 通常：可复现陈旧提交、错世界写入或重复结算为 P0；缺少现实可达乱序保护为 P1。

## DATA-01 数据平面与缓冲所有权

- 检查：AoS 用于控制平面，SoA/紧凑缓冲只用于有证据的高频数据面；容量、有效长度、稳定索引、版本和 owner 明确。区分对象遍历、显式复制、structured clone、transfer 与 Wasm 入/出拷贝。
- 检查：只 transfer 独立派生缓冲；权威或仍被读取的 buffer 不被 detach；共享只读视图不泄漏给可变消费者；缓存按 epoch/revision 或 dirty 范围失效。
- 通常：detach 权威数据、越界/陈旧读或语义不等价为 P0；无界复制或所有权模糊导致未来故障为 P1；未证明的微优化建议不成 issue。

## PROTOCOL-01 协议、存档与兼容

- 检查：公开消息、持久化格式、generator/schema/protocol 版本和消费者同步演进；未知/损坏/超限输入 fail closed；旧数据恢复、事务顺序和 durable 边界不被外观重构破坏。
- Node 文件存储：涉及 checkpoint 时核对 CURRENT/PREVIOUS 可达性、锁、在途读取、内容长度/hash/身份/版本校验及崩溃恢复。
- 通常：数据丢失、错误接受损坏状态、wire/存档不兼容为 P0；迁移或失败策略不完整但尚未触发为 P1。

## LIFE-01 资源生命周期

- 检查：Worker、timer、listener、GPU 资源、Object URL、音频节点、文件锁、临时文件、端口和进程在成功、失败、取消、切换与销毁路径都成对释放；重复释放安全。
- 通常：可导致错误状态、锁死或持续无界泄漏为 P0/P1；有界、低影响清理改进为 P2。

## ERROR-01 失败与用户反馈链

- 检查：保留现有错误通道和用户反馈；不要新增与正式路径竞争的静默 fallback。失败不能被伪装成成功，部分提交要么原子完成，要么有明确恢复。
- 通常：静默数据错误、错误成功或 fallback 绕过权威为 P0；可诊断性不足且会显著增加未来故障恢复成本为 P1。

## RENDER-01 渲染与资产边界

- 检查：体素保持 Chunk Mesh；PlayCanvas WebGL2 后端不被偷换成 WebGPU/GPU compute。材质、模型和 UI 是表现，不取得玩法/碰撞权威。导入资产边界核对尺寸、格式、外链、生命周期和明确失败。
- 通常：后端/权威边界改变或不可信资产绕过校验为 P0；资源释放或兼容缺口为 P1。

## TEST-01 测试语义与证据层级

- 检查：测试会在实现破坏时真正失败，覆盖关键反例而非复述实现；Vitest、构建、Playwright、Midscene、Harness、手工与性能证据只证明各自层级。历史结果必须绑定其 source identity。影响选择合并 base/head 依赖闭包，未知依赖或策略变更必须 full-new；空或无有效测试不得通过；生产 artifact 必须匹配 source/lock/字节身份。
- 检查：计数增长或输入 ack 前进不能单独证明目标操作生效；基线与 owner 完成边界对应，夹具显式定义环境，就绪条件只绑定被测对象。关键回归按风险核对定向故障反例；不要求每 PR 全仓 mutation testing，不把具体帧数/tick 数推广成通用门槛。
- 检查：测试按 owner 放入 workspace，ESLint 插件独立测试；跨模块集成归 Web，唯一 Classic 浏览器线路使用同一生产 artifact。历史 change 不作活跃运行依赖；长期基线准入须独立评审。生成物、mock、loopback 或启动日志不能冒充真实消费者。
- 通常：错误测试给出虚假安全感且放行 P0 行为为 P0；关键反例缺失或证据冒充为 P1；低价值重复测试为 P2。

## PERF-01 性能与技术优越性声明

- 检查：任何“更快/更省/零拷贝/SIMD 更优”都有同身份 A/A 噪声与受控 A/B，计入准备、复制、排队、回传和最终消费者指标；正式采样来自性能执行窗口。
- 检查：优化不改变正确性、权威或 fallback；microbenchmark 不外推端到端收益。
- 通常：以未证实性能理由引入正确性风险按影响定 P0/P1；仅缺少宣称证据为 P1，删掉无害夸大文字可为 P2。

## SCOPE-01 复杂度、复用与可理解性

- 检查：变更解决当前 spec，不为未知未来预建 `engine`、`plugins`、`shared` 或平行抽象；复用已有 helper/API 和错误路径。复杂解释应进入代码/文档，而不是只存在于 review 对话。
- 通常：复杂度造成可达错误或职责双轨为 P1；局部简化建议为 P2。个人风格不成 issue。

## COMPAT-01 冻结入口与生成来源

- 检查：新代码不得使用 `apps/web/src/app/player-view-offsets.ts` 或 `apps/web/src/client/performance-telemetry.ts` 兼容入口；生成文件、Wasm/SSG 产物和声明 exports 从权威源更新，不手工改派生产物。
- 已有自动规则若已精确报错，只在证据章节引用；仅当绕过方式造成真实语义风险时新增 finding。

## SECURITY-01 不可信边界与预算

- 检查：网络、磁盘、导入文件、URL、消息和用户输入在分配/解析/写入前有类型、长度、数量、路径和身份边界；错误不会泄漏凭据或内部数据；拒绝路径不留下部分状态。
- 通常：路径穿越、任意外链/执行、秘密泄漏、无界分配或身份绕过为 P0；现实风险存在但利用链未闭合为 P1。

## 维护规则

新增规则必须指向当前 `AGENTS.md`、长期 docs、已接受 spec 或真实事故证据，并说明为何静态检查不足。若规则可以低误报地确定性执行，应另开 change 将其升级为 lint/test，再从本目录删除重复人工检查。项目合同变化时更新权威文档和本目录，不能只修 prompt。
