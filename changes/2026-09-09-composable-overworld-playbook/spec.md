## Intent

让现有 MC 类玩法从核心特例变为第一方 API 消费者。作者可选择标准机制模块、配置其数据/规则，也可通过同一模块合同提供替代机制，而不 fork 引擎。引擎维持单一权威、可诊断的失败与可恢复世界；无大模型也能完整游玩。

阶段目标：**形成小内核、标准模块及模组 API 候选边界，以生存/创造规则和完整基础循环验证。** 基础循环是产品验收，不仅是冒烟；通过本期不宣称 API v1 永久稳定或达到现代整合包质量上限。

## Scope

### 用户确认

1. 先沉淀长期架构知识文档，再实施本期；模块是引擎认识的能力单元，Pack 是传播交付单元。
2. 小内核不包括渲染；标准机制模块与作者模块使用同一注册/调用规范；Playbook 是唯一组合根 Pack。
3. 不要求第一方签名认证，校验锁清单与包内容的哈希一致性；不将它称为来源认证或恶意代码沙箱。
4. 基础主世界循环加工具品质成长；生存与创造验证规则自定义。
5. FPS、高难生存、休闲、工业、经营/策略、RPG 等现代整合包参考由用户后续提供，不进入本期实现或质量验收。
6. 独立实施；用户补充允许以已合并 #25 为基线。

## Current evidence

在固定基线实读：

- `GameplayRuntime` 单独维护 `players: Map<string, PlayerState>`；`getInventory` 仍依赖 PlayerState。`EntityStore` 按固定 player/world-item/creature/npc 分支创建状态，不是目标组件合同。
- `ItemIds`、物品能力 union 与全局 definitions 固定；`createItemDefinitionRegistry` 尚未成为每世界装配入口。配方 registry 同样全局固定。
- 现有 `Inventory` 候选复制与替换、recipe 消耗产出、CombatRuntime 的阶段/连招、AutonomyRuntime、物理、世界事务可以复用，不从头重写。
- Gameplay 快照 V1/V2/V3、坐标/身体 schema 与旧迁移已存在。新格式必须保持这些受支持输入可恢复。
- #25 提供 Headless/Browser 共享 WorldHarnessPort、frontier、授权及 checkpoint。当前权限资源是封闭 union，scope 主要 self/any；全局开发观察不是普通角色感知。模块扩展需在本 change 内接入既有授权器，不新增平行 allow-all 通道。
- 既有测试/构建证据不是本 change GREEN。旧轮次本机 pnpm 曾被 devalue@5.9.2 发布年龄校验拦截；本轮按实际命令读回，不放宽供应链规则。

## Decisions

### D1 内核、模块和 Pack

内核承接身份、组件注册/生命周期、逻辑时间、调度、授权执行、事务、事件事实及检查点协调；紧凑体素是基础服务。物品领域、库存、标签语义、动作、伤害、合成、需求等为标准模块。渲染/输入/音频留 Web 宿主。

模块 descriptor 声明 namespace ID、版本、提供/需要的合同、组件/schema、资源/操作、生命周期与调度依赖；Pack manifest 声明六分面入口、模块清单、依赖、内容摘要与权限请求。模块同规范不等于业务可互换：provider 必须满足消费方的版本与语义合同。

先在现有 owner 下形成职责边界，不用先拆十几个 npm 包。新增职责簇可位于 `server/composition`（装配与公共合同）、`server/gameplay/modules`（标准领域模块）、`server/gameplay/playbooks`（第一方装配与内容）；ECS 适配留 `server/gameplay` 相关职责内。Web 分面在既有 app/gameplay、scene、ui 目录。实际移动前同步目录规范、代码地图和依赖正反例测试；不预建无消费者顶层 engine/plugins/shared。

模组只导入显式公开 facade，不能依赖 GameServer 私有实现、内部组件容器、PlayCanvas 对象或 ECS 句柄。现有 core exports 服务宿主/仓库代码，不直接全部升级为模组公开 API。静态负例拒绝标准 Pack 的内部导入。

### D2 装配与完整性

启动时先解析锁清单、校验包/资源摘要与版本，再收集注册、检查重复 ID/缺失引用/循环依赖/独占 provider/未批准替换，生成稳定执行顺序并冻结每世界定义，之后才创建或恢复状态。模块 import 不隐式启动世界或计时器。

本期加载仓库内构建的 ESM Pack 和锁定配套资源；实现真实 manifest/摘要校验与装配，不做任意 URL/压缩包市场。摘要计算在宿主工程适配，core 接受已验证的不可变描述并再次验证业务 schema。所有可信代码仍受公共接口约束，但不声称同一 JS realm 可隔离恶意代码。

一个世界恰好一个满足启动/恢复合同的 Playbook。组合根对已声明替换槽和冲突作最终合法选择，不能授予宿主未批准权限，不能让不兼容 schema 静默覆盖。相同锁清单/seed/generatorVersion 必须得到相同定义映射和规则顺序。

### D3 ECS 和状态迁移

采用组件化 ECS 方向，不将当前 Map 改名冒充迁移。复用现有调度/空间门面，先迁稳定身份、位置/身体、生命，再迁需求、库存/装备和控制状态；迁入字段的旧 API 只读新 owner 或转发操作，禁止双写。

ECS 库先做有界准入：bitECS 为现有路线首选候选，Koota 为对照。准入必须锁已发布版本、许可、依赖闭包并验证 core 纯逻辑、生命周期、旧引用、两世界隔离、存档恢复、空间/物理接入；不以新库或 SoA 名称宣称速度提升。现有 EntityStore 是行为对照，不是可以长期保留两套真相的 fallback。未通过不得擅自自建通用 ECS 或换库；需记录结果并重开选型合同。

该准入阶段的临时试验不导入生产；生产依赖与准确适配方案须写入准入记录并补充精确审核后安装。不得绕过供应链策略。持久 EntityId 不等于可回收 ECS ID；模组、协议和存档均不暴露内部编号。

### D4 规则扩展与授权

动作先做身份/范围授权，再做玩法条件；执行时形成候选效果，按明确 before/after 依赖与稳定 ID 顺序运行规则、校验注册状态不变量并提交，之后发布事实。声明式配置与代码入口走同一 owner。提交后订阅不可改旧事实，只能有界排队新操作；同步重入提交被拒绝。

规则修改/替换必须指向命名扩展点；模块可注册新 Action、资源和事件，不能暴露任意内部函数为 hook。动作接受不预授权未来命中，执行检查点重新验证目标/规则/控制来源和版本。跨库存、耐久、方块或实体的操作要么一致提交，要么无副作用；首次支持范围由注册参与者构成，不承诺任意外部 I/O 事务。

复用 #25 principal/resource/operation/target 模型及 deny 优先。扩展资源目录与实际执行映射同 owner；调用上下文携带宿主绑定主体、Pack/模块来源和原始角色，不能从请求参数自授身份或借模块权限提权。未注册资源、未知主体、未授予 API 均拒绝。权限检查在返回受保护数据或执行规则前；Headless 开发管理员仅用于搭场景，不作为普通动作验收凭据。

本期不依赖未来 visible/area ACL；self/any 以真实主体/目标检查，正常攻击/采集另检查距离、碰撞与动作条件。新增模块只获得必需能力；Playbook 不能关闭内核身份/完整性校验。

### D5 物品、合成与模式

物品定义 ID、堆叠、实例状态分离；耐久不同实例不能无规则合并。配方引用物品/tag，不隐式创建物品。标签表达材料等价，由定义/有效状态计算，不能凭名字判断工具品质或矿种。

合成拆为匹配/条件/消耗产出事务与工位/交互策略。本期标准 provider 支持无序基础合成与3×3有序匹配；基础冶炼使用逻辑时间、燃料和进度组件。输出阻塞时不丢料、不重复产出；工作台/箱子/炉体随方块生命周期销毁时按定义结算其内容，不能遗留孤儿库存。自定义点击转换样例使用不同匹配 provider，但复用物品与事务合同。

角色模式与世界 ruleset 分离；第一方只提供 survival/creative 两种模式。默认生存；世界创建可选模式，单玩家可经获授权入口显式切换。生存有资源消耗/饥饿/伤害/死亡；创造用独立目录快捷引用，不修改生存库存数量，关闭对应需求/伤害，提供飞行及即时编辑。

切换时终止不兼容在途动作；两种快捷栏分开保存，切回生存恢复原库存/耐久，停止创造飞行，按物理流程验证落脚（无安全落点则拒绝切换且不改变原状态）。创造放置的地形作为明确编辑保留；不宣称混用创造后的世界仍保持纯生存资源守恒。模式变更与规则 revision、存档一致提交。

### D6 生成、保存和宿主

保留旧 generatorVersion 与数值 ID 映射；新增矿物生成使用新版本，旧存档不重新生成已有/未编辑 Chunk 为另一套规则。体素仍为紧凑数值，内容 namespace 与数值映射由版本化装配登记，不直接使用字符串存每格方块。

新存档引用锁定 Playbook、Pack/模块内容摘要、注册映射、组件 codec/schema、规则版本，并与地形/流体等同 frontier 保存。为主干支持的 V1/V2/V3 输入保留显式迁移到默认第一方装配；旧工具的无耐久状态按版本化默认值迁移一次并记录。缺少必需包/不兼容 schema/坏摘要在替换当前世界前失败；不删除未知物品或默认为空气。

Browser/Headless 从同一 checkpoint 恢复后比较权威事实和显式推进，不比较跨 epoch 的运行 tick 原值。客户端只持有派生投影；资源、动画、HUD 和音效不决定权威采集/命中。继续使用主干 Harness，不复制 REPL、权限或新建第二套世界执行器。
