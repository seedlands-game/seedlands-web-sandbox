# 热路径第二轮实验报告

## 结论

本轮不采纳 M/P/C 三个性能候选。三个候选均完成 RED、实现和定向功能验证，但正式 v2 control A/A 的 Authority CPU 相对极差为 23.64%，超过预注册的 20% 停止线，因此未进入 ABBA，也不声明任何性能收益。生产候选已撤回，补丁保留在 `experiments/candidate-m.patch`、`candidate-p.patch`、`candidate-c.patch`。

保留并交付 Classic 性能场景 v2。视觉改版已退出 settler，旧 v1 旅程在 C0 请求已不存在的角色配置而失败。v2 保留固定 seed、采集、制作、战斗、建造、四个 Chunk 中心往返、资源界限、保存恢复与恢复后真实输入；明确不覆盖 NPC 行为。v1 历史样本不得与 v2 构成性能 A/B。

## 场景迁移证据

- v1 失败 `hotpath-r2-aa1`：`Unknown actor profile: settler`，与候选无关，保留为旧场景失效证据。
- v2 首次失败 `hotpath-r2v2-aa1`：恢复后物理继续运行，Y 从约 60.77 落到 60.00；X/Z、玩家身份、生命和背包一致。合同修订为持久化字段与水平位置，Y 仅要求有限且不高于保存点。
- v2 smoke `hotpath-r2v2-smoke2`：完整 C0–C5 通过。`scenarioId` 为 `classic-canonical-runtime-v2`；世界 seed 仍为 v1 字符串，以保持地形负载。

## A/A 结果

三轮正式样本 `aa4/aa5/aa6` 均通过 C0–C5、measurement digest、源码/产物身份和独占窗口审计。`smoke2` 仅验证合同，不进入噪声计算。

| 指标                    |    aa4 |    aa5 |    aa6 |   相对极差 |
| ----------------------- | -----: | -----: | -----: | ---------: |
| Main CPU ms/s           | 186.24 | 185.28 | 191.92 |      3.56% |
| Authority CPU ms/s      |  90.16 |  82.61 | 103.93 | **23.64%** |
| Main+Authority CPU ms/s | 276.40 | 267.90 | 295.85 |     10.11% |
| frame p95 ms            |   17.9 |   18.5 |   17.8 |      3.91% |
| chunk visible p95 ms    |  566.8 |  566.2 |  568.0 |      0.32% |

预注册规则要求主指标 A/A 噪声不超过 20%。M/P 的主指标均为 Authority CPU，因此本轮无法有理据地判断其收益；继续补跑并挑选稳定样本会破坏预注册合同。C 虽以 Main CPU 为主指标，但本轮三个候选原定在同一实验窗口和组合裁决中推进；总 CPU 噪声已达 10.11%，且用户要求“确保有理有据”，故不单独采用 C。

## 证据边界与后续

本轮证明 v2 场景可运行、窗口没有重叠、当前机器上的 Authority 采样不够稳定；不证明三个候选无收益。若未来性能重新成为卡点，应在更安静的机器窗口重新执行 A/A，并从头跑各候选 ABBA，不沿用本轮停止前的对照。

长期 docs baseline 更新 `docs/performance-execution.md`，因为现行性能场景身份从已失效的 v1 迁移到 v2；没有把候选实现写入长期架构文档。

rebase 到最新 Classic 体验提交后，真实鼠标 C2 首次验证暴露 Pointer Lock 重锁竞态：边界移动触发解锁时暂停层仍可见，旧 helper 点击“继续”后未等待层隐藏，后续俯仰输入全部落在暂停 UI。Harness 现以暂停层隐藏和浏览器 `pointerLockElement` 为完成边界；不降低真实输入或目标方块断言。失败样本保留，修复后重新执行生产旅程。
