# 路由与职责

先判断确定性脚本能否完整表达输入、边界和验收。可表达时用 `execution.form=script`，`model` 与 `effort` 为 `null`。脚本不能表达的判断工作再按默认路由：

| 工作                                       | 默认路由                    | 落地形式 / 典型闭环                                       |
| ------------------------------------------ | --------------------------- | --------------------------------------------------------- |
| 可机器判定的固定转换                       | 无模型                      | `form=script`，一次准备后有界执行并机器验收               |
| 明确的长开发                               | `gpt-5.6-sol/high`          | 单次 `subagent` 端到端实现、自测、修复                    |
| 执行验收与回归核查                         | `gpt-5.6-terra/high`        | 单次独立验收 `subagent`；跨请求反复承担才建立固定独立职责 |
| 限定资料提取                               | `gpt-5.6-luna/medium`       | 有界只读提取，不开发                                      |
| 纯文本机械扫描                             | `gpt-5.3-codex-spark/xhigh` | 输入输出明确的纯文本任务，不开发                          |
| 顶层标准、MVP 设计、模糊探索、复杂 UI 实现 | `gpt-6-astra/high`          | 当前任务或有界 `subagent`，闭环设计、实现或取舍           |

默认档位可按任务成本、能力和既有项目基线有理由调整，偏离时在 `execution.routeReason` 记录具体原因。不能用泛化理由绕过“明确长开发默认 Sol”的标准；Luna 与 Spark 不承担开发，Spark 只做纯文本机械任务。人类直接选择的模型始终保留。

subagent 负责有界单次闭环。只有跨请求复用的固定职责才考虑独立任务；创建独立任务必须已有用户授权并满足平台工具要求。嵌套派发者必须生成子合同，继承父范围、权限、预算与升级条件。平台并发限制优先，无法并发时顺序执行，不把机械工作退回主任务。

比较总成本时同时计入执行、上下文、协调、返工和验收；工具等待不等于模型工时，也不要为了单次模型更便宜而制造更多交接。价格需要使用时动态核对，credits、token 和实际账单分别记录；父 agent 汇总整棵任务树的分配与消耗。

Midscene 在用户预算规划中可按近零增量成本估算，但真实运行可能依赖模型、密钥和服务，不能宣称免费。可程序化行为优先确定性浏览器测试，视觉语义才使用 Midscene。
