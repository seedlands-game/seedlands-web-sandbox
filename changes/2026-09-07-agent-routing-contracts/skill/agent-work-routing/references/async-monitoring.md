# 长异步监控

监控是一次有界的只读等待，不是新调度器、持续代理或隐含的外部写入。优先顺序为平台终态事件、已有原生 `wait`/`watch`、确定性单次状态查询；只有前述能力不足时才使用低频心跳。

## 监控合同

交接必须记录任务或 run id、来源 SHA、归属、状态来源、截止时间、回报对象和允许的终态。状态至少区分 `pending`、`success`、`failure`、`cancelled`、`deadline`、`head-changed` 与 `needs-decision`。状态来源不能证明的终态应标为 `unknown` 并回报，不得猜测成功。

主任务交出监控后应结束当前活动轮次或处理独立工作。不能默认把普通 subagent 返回当作有保证的跨轮次唤醒；需要通知时必须使用已存在的平台终态事件、心跳或明确的回报路径。不得让主任务按固定间隔重新查询或询问 worker。

## 回报与停用

每次心跳只读取一次紧凑状态。`pending` 静默；`success`、`failure`、`cancelled`、`deadline`、`head-changed`、`needs-decision` 和 `unknown` 都必须向约定回报对象给出 run id、来源 SHA、状态与最小证据，然后立即停用监控。HEAD 变化使原监控终态化，不能把新 HEAD 当作同一次 CI；取消和截止同样不自动续期或重试。

CI 失败由 `Terra/high` 提取最小失败证据；修复范围明确后才交 `Sol/high`。架构、权限或范围不清的问题回到主任务。纯文本机械状态归约可使用可用的 `Luna/medium` 或 `Spark/xhigh`，但需要判断的监控不降档。若平台心跳不能单独指定模型，只能以低频和少量唤醒控制成本，不能宣称使用了低价或免费模型。

## 场景核对

| 场景                          | 监控动作                                                       | 回报与终态                                                   |
| ----------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------ |
| CI 还剩 7 分钟且仍在运行      | 建立有截止时间的只读 `wait`/`watch` 或低频心跳；主任务退出轮询 | `pending` 静默；成功、失败或截止时一次回报并停用             |
| CI 失败                       | 保留 run id、来源 SHA 与最小失败摘要                           | `failure` 回报；不自动重跑、修复、合并或部署                 |
| HEAD 改变、取消或到达截止时间 | 终止原监控，不沿用旧 run 到新 HEAD                             | 分别回报 `head-changed`、`cancelled` 或 `deadline`，随后停用 |
