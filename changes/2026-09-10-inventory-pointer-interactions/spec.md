# 背包与工作台鼠标交互

- 批准记录：用户批准 SHA-256 `3862602180748324e55b82c561a3515760ea62fa3e097eef988a3244f792eda9`；原文冻结于 [spec-approved.txt](evidence/spec-approved.txt)。本文件后续仅更新状态与交付记录，原批准行为合同保持不变。
- 最新授权边界：按用户“实现+本地验证后先让我验收，先不处理 ci 问题”，本轮只做本地提交与试玩交接，不 push、更新 PR 或处理 CI。

- 用户原话：“这个背包和工作台的体验也太差了 至少应该对齐minecraft的体验吧 让物品可以拖拽放置 区分左键右键等基础的逻辑”。

- 硬约束：数量与耐久身份守恒；支持现有存档；Headless/Browser 规则一致；保持 24 格背包、8 格快捷栏、既有物品/配方与生成器。

## 实施前现状与推荐

已读取 `inventory-crafting.svelte`、`station-panel.svelte`、`browser-gameplay.ts`、`browser-stations.ts`、`inventory.ts`、`inventory-action-model.ts`、`station-action-model.ts` 与 ECS Actor owner。现状只有点击选中源格/目标格；工位数量靠“每次移动整组”复选框；没有游标持物、左右键或拖拽手势。底层 `Inventory.split()` 支持部分拆分，但正式库存 move 操作没有数量，工位 transfer 只支持 Actor 与工位之间传递，且拒绝不同物品交换。

推荐复用库存/工位的 candidate → 授权 → 原子提交机制，加上同一 owner 管理的游标持物状态；浏览器使用 Pointer Events 处理手势与预览。背包、快捷栏、箱子、工作台和炉体共用槽位交互组件。

比较：

- 仅包装既有两个点击：无法实现完整拆半、持物交换、工位内部移动和连续铺料，排除。
- 仅在浏览器维护被拿走的物品：保存、死亡、窗口关闭或命令拒绝时会产生第二份状态 owner，排除。
- 引入通用 DOM 拖拽库：仍须自行处理右键、游标、数量分配与权威事务；当前已安装的 Svelte 和浏览器 Pointer Events 足以承载这些手势，因此本次不新增依赖。不声称已评估全部第三方库或其性能。
- 改成权威游标并复用领域事务：增加的状态/协议有明确用途，能覆盖满背包和部分堆叠交换；采用。

参考 [Minecraft 官方基础操作介绍](https://www.minecraft.net/en-us/article/minecraft-controls)。官方介绍只用于菜单/基础输入背景；下列精确分配规则是本 change 冻结的产品合同，不宣称逐条引用了官方或已完整复刻某个游戏版本。

## Scope 与 Decisions

1. 实现生存库存、工作台、箱子和炉体统一的游标持物、左右键、拖拽、快速转移、快捷栏交换与工作台结果槽。
2. 取消“每次移动整组”复选框与强制先选再按操作按钮的主路径。已有食用入口和配方查询保持可达。
3. 布局：容器/工作台在上，背包在下，8 格快捷栏单独成行；工作台呈现 3×3 输入、箭头和结果预览；槽内主要显示图标、数量、耐久条，悬停显示名称/耐久，游标显示实际持物及数量，拖拽目标显示分配预览。
4. 保留项目自己的素材与视觉风格；不复制 Minecraft 资产。维持现有容量和配方，不新增 2×2 个人合成、装备/副手、触屏、手柄、中键创造复制或物品管理模组功能。创造目录本轮保持既有选择行为。
5. 公共操作合同新增有界的槽位交互请求，保留现有 move/transfer 调用的旧语义。来源与目标明确区分 Actor、工位、结果；游标绑定 Actor 的 epoch/lifetime。由原始 Actor 权限校验，不提升为开发者身份。
6. 游标物品进入权威 Actor 的可保存、可检查状态，不进入仅 UI 的临时库存；用独立版本化字段/组件表达，不增加可用背包容量、不重用某个普通格子。现有 V1–V4 存档由显式适配补空游标，保留库存/工位内容、耐久及世界生成身份；旧内容摘要与新内容关系必须走明确迁移，不能放宽任意坏摘要拒绝。若无法保持受支持存档，则停止并重开方案。
7. 请求带会话顺序/受影响库存版本与工位引用/版本；一次拖拽分配为一次有界原子事务。重复/过期、越距、工位销毁、非法目标或数量必须无部分扣料地拒绝。浏览器按响应确认状态，预览不能成为权威；命令失败走现有反馈入口。

## Behaviour

| 操作                   | 行为与边界                                                                                                                                                                  |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 空手游标左键           | 拿起整组，源格清空；数量及实例身份保持。                                                                                                                                    |
| 空手游标右键           | 拿起向上取整的一半，例如 9 件拿 5、留 4。                                                                                                                                   |
| 持物左键               | 空格放整组；相同身份合并到堆叠上限，剩余仍持有；不同身份交换，受容器槽位限制。                                                                                              |
| 持物右键               | 向空格或相同身份槽放 1 件；满格不扣物；不同身份按合法整组交换，不把不同耐久工具合并。                                                                                       |
| 拖起后松到一个槽       | 支持直接按住源格拖到目标格放置，和先点击拿起再点击放置两种操作；开始拿起的那次按压不误触发批量分配。                                                                        |
| 已持物时左键拖过多个槽 | 松开时向去重后的合法目标均分：每格分配 floor(持物数/目标数)，各格按剩余容量截断，余数留游标；不足每格一件时不分配。                                                         |
| 已持物时右键拖过多个槽 | 松开时按经过顺序每格放 1 件，回经过同格不重复放；物品不足时只覆盖前面足量的目标。                                                                                           |
| Shift + 左/右键        | 无持物时整组快速转移；有容器优先容器↔背包，无容器时背包↔快捷栏；先合并同类再用空格，容量不足保留源格余量。炉体只接受合法原料/燃料，产出只能取出。持物时不触发快速转移。     |
| 双击左键               | 汇集当前可访问背包/容器中相同身份物品到游标上限；不从工作台结果预览制造物品，不突破只读/距离限制。                                                                          |
| 悬停按 1–8             | 与对应快捷栏格交换，容器规则照常校验；持物或正在拖拽时不再叠加快捷交换。                                                                                                    |
| 合成结果               | 根据当前 3×3 格显示可制作的结果；点击结果取一批到空/兼容游标并原子扣材料；Shift 点击按材料与背包剩余空间有界制作到背包。空间不足不扣料，结果格不能放入物品。                |
| E / Escape / 关闭      | 结束拖拽预览；已拿起物品先归还原格可容纳部分，再合并背包/空格；放不下的余量通过正式掉落路径落在玩家处。工位材料维持当前持久工位语义，不额外清空。                           |
| 点窗口外               | 持物时左键丢整组、右键丢 1 件，通过正常掉落事务；点对话框内部留白不丢物。                                                                                                   |
| 中断与失效             | 失焦/指针取消只取消尚未提交的拖拽预览；工位不可达后不得继续访问旧工位，游标已拿物仍属于玩家；死亡把库存及游标恰好掉落一次，复活无重复。切模式先结算持物，再执行原模式规则。 |
| 保存/恢复              | 保存期间持物纳入同一快照；恢复/重新进入时先按关闭规则结算或恢复可访问的游标，不能静默删掉。Headless/Browser 往返保留同等数量、实例及工位状态。                              |

## Test Design 与 Acceptance

实施前先执行失败用例；缺少新接口导致的编译失败仅记缺接口，行为 RED 用既有浏览器页面的右键/拖拽实际输入断言证明。每项最终记录绑定 source 与运行结果，不使用固定睡眠冒充就绪。

- T1 纯状态/事务：9 件右键拆成 4+5；单放、满格溢出、不同身份交换、耐久工具不合并、非法数量拒绝；数量与实例身份守恒。
- T2 分配：10 件左拖 3 格得到 3/3/3、游标 1；右拖 3 格各 1；重复经过、满格、非法炉体槽、少量物品及取消手势。
- T3 容器：Actor↔工位、工位内部、快捷栏交换、Shift 部分装满、炉体输入/燃料校验与结果只取、双击收集边界。
- T4 原子性：过期版本、重复请求、工位销毁/失距、权限拒绝、中途失败不部分扣料；快速连续输入不重放或丢指令。
- T5 合成：真实右拖铺木镐图案、拿一次结果、Shift 批量、满背包/不兼容游标拒绝；材料与产出严格守恒。
- T6 生命周期：持物关闭、窗口外掉落、失焦、满背包归还、死亡/复活、模式切换；保存恢复及旧 V1–V4 迁移、坏摘要继续拒绝。
- T7 真实浏览器：用 mouse.down/move/up 的左/右键与 keyboard 操作完成拆半→铺料→制工具→容器整理→保存重进，核对 UI 和权威状态；不得用直接改库存代替被测操作。夹具仅准备明确的初始材料/工位。
- T8 界面观察：背包/工作台/箱子/熔炉截图，游标与拖拽中间帧，桌面视口下槽位及操作提示可读；右键不弹浏览器菜单，背包输入不穿透世界攻击。使用者最终手感仍需试玩，不以静态测试宣称视觉满意。
- 基础准出：受影响 Vitest/类型检查，`pnpm verify:static`、`pnpm build` 分别通过；定向 Playwright、新旧基础成长/背包回归按当前行为合同选择。历史 Delivered 断言不能静默改成新语义。
- 新协议/生命周期与事务边界独立审阅，发现修复后再验收；仅本 change 的语义提交；按既有授权 PR 交接，不自动合并。旧续跑 automation 保持暂停。
