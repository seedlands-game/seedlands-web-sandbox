## 需求与技术假设分栏

| 类别           | 本次固定内容                                                                                                                                                      |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 用户获得的体验 | 一个玩家与一个 NPC 在浏览器单人世界共处；NPC 有正式身份、性格、目标、真实身体与背包，按正常规则行动，能被打断、失败或死亡；玩家可观察、干预并保存它造成的后果     |
| 长期愿景       | 幻想实例化为成熟可玩世界；持续因果、再访发现、引导式创作与低运维平台。世界不围绕玩家做预写剧情                                                                    |
| 硬约束         | WebGL2；浏览器 Authority Worker 单写者；本机 Agent Server 只负责认知；浏览器主动双向连接；共享世界 Harness；本期不做模拟 LOD、离线追赶、World AI、多人和 UGC 平台 |
| 技术假设       | 复用现有 Authority/Action/Physics/Inventory 足以做最小角色统一；薄 SDK 宿主可承接模型调用；JSONL 与 WS 只承载版本化信封。这些需要分阶段验证，不声称现状已经支持   |
| 关键未知       | NPC/玩家 Inventory 与战斗/动作 owner 合并的实际接缝、浏览器显式世界推进的异步屏障、跨保存恢复的 Agent 记忆确认、模型在受限工具上的稳定性                          |

“完全像另一个玩家”冻结为**本切面的规则平权**，不是无限能力或人类智能承诺。动作/物品/距离/耗时/碰撞/资源/生命规则一致；控制方式、主观偏好和角色获知的信息可以不同。无法做到的动作必须明确返回 unsupported，不能通过开发者命令作弊补齐。

## 推荐交付体验：营地伙伴

固定一个可恢复场景：玩家和持久 NPC“阿岚”在同一营地，周围有浆果、木材和一段可编辑地形。阿岚谨慎、愿意分享但优先保留口粮，自己的目标是补足口粮并修好营地三块标记围边。

1. 玩家进入，看到阿岚的名字、身体、当前可公开行动，并能近距离文字交流。
2. 阿岚先观察到可达食物，移动、拾取到自己的背包、在需要时食用；余量与共享选择受人格/目标影响。
3. 通过正常采集/放置规则完成一个微型环境目标，玩家看见地形改变和材料消耗。设计不要求完整建造规划器。
4. 玩家抢走食物、堵住路径或改变目标地块。阿岚收到失败/新观察后改选可行路径或目标，可以求助或放弃；不能预知玩家尚未实施的变化。
5. 玩家攻击、危险或断开 Agent Server 时，即时层继续工作，不等模型回复；未授权、过期、重复请求不改变世界。
6. 保存、关闭并重新进入后，同一 NPC 身体、Inventory、人格、目标、已确认经历和环境后果恢复；在途动作按明确恢复策略终结后重新决定。本期不补算离线时间。

场景夹具可由 Developer Harness 建立；验收动作必须由真实玩家输入和 NPC Actor Action 完成。NPC 不以硬编码脚本完成整条固定故事；可用脚本 provider 验证工程合同，但最终产品验收还必须使用真实模型。

## 非目标与准入边界

不重启 Node Dedicated 产品，不做通用行为树/GOAP、大规模 ECS 替换、通用建筑规划、多 NPC 认知调度、World AI、模拟 LOD、离线追赶、联网玩家、生成器/UGC/支付，也不选择最终商业模型和许可证边界。GroundNavigator 先用当前有界路径能力，复杂跨世界寻路不是本切面目标；失败必须真实可观察。

设计验收是合同足够具体、现状与计划分开、风险有关闭路径、可拆阶段能服务同一体验。运行时验收全部为 NOT_RUN；不能将这份设计、静态检查或脚本 Agent 当作 NPC 产品已经交付。
