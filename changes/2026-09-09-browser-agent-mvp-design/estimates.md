# MVP 实施估算与成本边界

2026-09-09，版本 E1；设计阶段的规划估算，不是实测工期、账单或实施授权。范围为 H1–A3，不含已经单独执行的 Node 归档、不含 LOD/World AI/生成平台。尚无同规模校准样本，置信度低至中；不能按“AI 是人类几倍快”换算。

## 工作量与连续时间

| 阶段                        | 传统工程量 PD（正常–保守） | Agent 活跃小时 | 不可重叠工具/联调小时 | 主要不确定性                                    |
| --------------------------- | -------------------------- | -------------- | --------------------- | ----------------------------------------------- |
| H1 共享合同 / REPL          | 2–3                        | 4–6            | 1–2                   | 屏障、显式时钟和可移植恢复                      |
| H2 Browser 一致性           | 2–3                        | 4–7            | 1–2                   | Worker 与 Headless 异步顺序                     |
| A1 Actor / Action 平权      | 4–7                        | 8–16           | 1–3                   | player(id) 假设、Inventory/近战 owner、地形交互 |
| A2 Agent 桥接 / 记忆 / 权限 | 3–5                        | 6–12           | 1–2                   | SDK、取消、保存切面和配对                       |
| A3 完整可玩验收             | 2–4                        | 4–8            | 2–3                   | 真模型可靠性、连续视觉、干预与恢复              |
| 合计                        | 13–22 PD                   | 26–49          | 6–12                  | 含必要评审、上下文交接与一次修复                |

1 PD=8 小时熟悉项目的工程师有效工作。单个活动 Agent 顺序基线为 32–61 小时，24h 连续条件下约 1.3–2.5 天；保守 61×120%=73.2，向上取整建议 **74 小时**规划预算（约 3.1 连续天）。现实日历还取决于用户审核、模型/账户和依赖服务，这些外部等待未伪装成零。

可以并行研究接口或 SDK adapter，但世界合同冻结、保存/权限整合和最终机器验收仍有顺序依赖；本估算没有把并发当成免费加速，也不隐含创建多个工作者授权。首个 H1 完成后用实际用量/返工重估剩余阶段，不能按本表盲目连续投入。

## 模型、token 与双费率

拟议实施路由：Astra/high 设计与架构裁决，Sol/high 明确开发，Terra/high 验证；默认标准速度。它们是未来分工估算，不是替换用户当前选择的模型。以下 token 是应用工作单元假设（每阶段 2–4 个设计/实现/验证单元，包含必要重复上下文和一次修复）；U=未缓存输入，C=缓存输入，O=含计费 reasoning 的输出，单位百万。保守按正常用量 2 倍覆盖上下文膨胀、返工与验收，不再重复增加阶段内 buffer。

费率于 2026-09-09 从[官方 credits 费率](https://learn.chatgpt.com/docs/pricing)和[API Pricing](https://developers.openai.com/api/docs/pricing)打开核对。API 模型比较页未给可解析单价，因此使用正式 Pricing 表。假设标准短上下文、不额外 cache-write、区域或图像计费；实际若使用 Fast/长上下文/额外工具需重新核价，本表不是账单。credits 与 API 等价是两种计量，不能相加，也不从一种倒推出另一种。

正常 259 credits / $10.36；保守 518 / $20.72；一次 20% buffer 后建议预算 **622 credits / $24.87 API 等价**。Astra Fast 会改变倍率，不能沿用此预算；实际部署 profile 必须在实施阶段确认。未来游戏 NPC 的运行时模型费不属于上述开发费用，A3 真模型测试调用另设有限额度；模型/provider 未选，当前 unknown，不填 0。

## 当前额度快照与预测占比

本轮通过 Codex `get_usage_limits` 于 2026-09-09（Asia/Shanghai）读取：账户共享 Codex 周窗口使用 59%、剩余 41%；额外消费 credits 余额约 511。快照含其他任务，不是本 change 专用预算；没有 included window 的 token/credit 总容量，**本 change 对剩余 included allowance 的预测占比 unknown**。Spark 单独窗口不纳入本设计拟议模型预算，不能与 Codex 桶相加。

若假设全部用额外消费 credits，正常规划 259/511≈50.7%，保守加缓冲 622/511≈121.7%；后者超出当前额外余额。这是条件对照，不说明 included allowance 不够，也不授权购买、兑换 reset 或继续付费。正式实施先选小阶段预算、完成后校准；不可把账户周额度百分比与额外 credits 当同一分母。

## 实际、缺口与重估

本次为设计交付，H1–A3 实际完成数为 0；真实模型调用未进行。当前设计自身的精确输入/缓存/reasoning token、分模型 credits 和 API 账单不可从账户共享快照可靠归因，记录 unknown。Node 退役实现的实测与工具时间归其独立 spec。

H1、H2、A1、A2、A3 阶段结束均登记：已耗/剩余/完工估计、实际工具时长、分模型 usage 可得性、失败与返工原因。建议更新公式为“已耗 + 1.2×保守剩余”，不重新加一次整项预算。估算超限时先保存可恢复状态再收敛范围；不通过省掉权限/真实浏览器/保存验证来压数字。
