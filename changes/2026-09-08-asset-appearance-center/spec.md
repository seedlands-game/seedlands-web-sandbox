# 对象外观与统一资产生产

状态：Active。类型：Breaking。用户已明确批准收拢此前方案、按设计与优化边界实施，并要求灯笼MVP通过后直接推广全部现有素材；本合同记录该明确授权，不重复要求hash确认。基线68bf592，既有PR #16尚未合并，本change在其上叠加独立分支交付，不自动合并。

## 目标与决定

统一入口 → 对象外观引用 → 可编辑模型/材质/图像源 → 可重建运行网格/纹理数组/图集/缩略图 → 版本化资源包 → 按需GPU资源。先验证灯笼，再覆盖当前全部108项内置资产、原生草稿和导入模型。用户导航不再暴露九种内部适配类型；底层保留必要的表示方式与能力限制。

每个资源只有一个编辑源；引用复用、显式覆盖、草稿与应用快照分离。世界/碰撞/方块ID仍由原owner管理；普通方块保持Chunk Mesh。GLB仅静态支持，不因导入自动注册玩法。GPU对象不持久化、不跨Application复用。

## Scope

- 对象外观/资源库工作区：同页材质槽、纹理编辑、预览和用途信息，保持模型视角；全量目录覆盖，来源与类型筛选分离。
- 灯笼纯几何同源，放置/手持/掉落/图标复用；普通方块物品使用同源面材质；兼容静态部件合并、共享缓存和引用释放。
- 统一外观项目覆盖：模型材质与像素源可编辑、共享与对象专用覆盖明确；预览、保存、应用、恢复分别可见。像素源保持16默认，不降采样旧32/64；高清缩略图独立生成。
- 项目包导出恢复包含必要源、引用和GLB；校验失败/版本冲突不留下部分应用。旧库保留读取能力，不覆盖用户无关世界。
- GLB稳定ID重导入，revision变化，失败保留原模型；不支持的材质槽/用途有明确反馈。
- 同引擎缩略图与模型预览/运行使用相同资源；全部内置对象进入统一工作流，能力不支持的操作说明边界。
- Blender已有CLI配方和导出验证纳入可复现项目脚本/说明；不新增MCP/Blender/Blockbench依赖安装。
- noa优化：共享几何、兼容材质分组、派生失效与释放纳入主线；灯笼实例化为有界A/B，若收益不足或占用验收缓冲则不启用并记录结论。

## 非目标

骨骼动画、完整DCC/Prefab/玩法编辑、任意GLB替换地形、服务器同步、空块/同质层mesher优化、halo与大坐标重定位、GPU后端迁移。统一管理不等于所有源在浏览器内都能编辑任意几何。

## Behaviour / Test Design

1. Given灯笼，When编辑材质并预览/保存/应用/刷新/恢复，Then放置、手持、掉落和图标引用正确，失败保留最后可用快照；真实浏览器与运行截图验收。
2. Given共享材质，When修改共享或复制专用覆盖，Then影响范围正确，专用覆盖不污染其他对象；确定性引用/版本与浏览器编辑验收。
3. Given全量内置目录，When进入对象与资源库，Then旧ID全部可定位、内部来源类型不占主筛选、模型关联编辑不丢选择与视角。
4. Given项目包，When空库恢复，Then源、绑定与导入GLB一致；缺引用、超限、无效GLB和版本冲突拒绝写入；应用快照完整切换。
5. GivenGLB重导入，ThenID稳定、revision递增、预览失效重载，非法输入不覆盖旧文件。
6. Given模型复用和反复切换/卸载，Then兼容网格缓存共享、资源最终释放、异步陈旧结果不提交。
7. Given同源灯笼，When对照Chunk合批与实例化，Then固定模型/材质/镜头比较draw call、bytes、CPU帧耗时、编辑延迟和释放；不以算法名称冒充收益，不降低AO/画质来通过。
