# 资产工坊：统一管理与按类型适配

## 状态与目标

- 状态：Delivered（本地验收完成，PR 与最新 HEAD CI 待读回）；用户已明确批准执行本稿，批准时 SHA-256 见 execution.md。
- 类型：Breaking，涉及资产持久化、跨模块表现复用与独立产品入口。
- 用户最新决定：所有物品资产应在同一处展示和管理；不同类型资产使用不同生产、编辑和预览适配。不可放置手持物品是当前像素挤出工具的适用范围，不是资产工坊的整体范围。
- 长期目标：玩法所引用的模型、贴图及后续动画/材质等资产有统一目录、来源、版本与依赖关系；游戏和编辑器消费同一资产运行实现。
- 首版退出条件：所有当前已注册物品及其关联资产可查；工具像素编辑形成保存、恢复、导出、3D/手持预览闭环；原有 PNG 与其他物品模型通过各自的真实预览证明多类型适配。

## 关键区分：资产、用途与可编辑源

资产记录描述“是什么”，用途绑定描述“谁在哪里使用它”，适配器描述“能做什么”。

- 资产：一份有稳定 id、类型、版本与来源的模型/贴图等资源。
- 物品：玩法定义，引用图标、手持模型和掉落展示等资产；物品不是某种模型文件类型。当前物品注册的权威来源仍为 `src/server/gameplay/item-registry.ts`，不在工坊另造物品真值。
- 用途：物品图标、第一人称/第三人称持握、掉落、方块、实体等语义，由引用方决定。一个 PNG 不能仅凭扩展名推断为可放置或不可放置。
- 可编辑源：像素矩阵、模型参数，或外部艺术工具的母版；运行产物是网格、纹理等。通用管理不等于把所有格式转成像素挤出模型，也不把 GLB 预览能力当作完整建模能力。
- 管理入口名称为“资产工坊”。左侧可切“按物品查看”与“按资产查看”：前者展示某物品关联的模型/贴图，后者按资产 id 去重并展示所有引用方。

## 首版 Scope 与能力矩阵

独立 `asset-workbench.html` 入口，使用既有 Svelte、PlayCanvas WebGL2，不启动游戏世界、物理、Worker 或 Pointer Lock。

| 类型 / 适配                    | 首版展示与预览                                                   | 首版编辑能力                                        | 边界                                                               |
| ------------------------------ | ---------------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------ |
| `pixel-texture`                | 像素、透明棋盘、调色板、派生图标                                 | 16/32/64 画布、画笔/橡皮、调色板、撤销/重做         | 可编辑原生源，最多 32 色，不支持半透明和图层                       |
| `extruded-pixel-model`         | 真实 3D 转台、握持、挥动/采集/收手                               | 关联像素贴图、总厚度、握持点                        | 当前绑定只允许木斧、石镐；不覆盖可放置物、方块/异形方块或角色/生物 |
| `image-texture`                | 当前内置物品 PNG、透明背景、尺寸和用途；原始像素及平面采样对照   | 首版只读图像，展示来源；不把 PNG 默认为原生像素工程 | 图像替换/绘制后续另拆；派生图标指回其源，不能独立手改              |
| `builtin-item-model`           | 方块物品、灯笼、浆果、木板等已有程序化模型，调用游戏原有表现实现 | 首版只读，显示关联物品、来源和可用预览模式          | 这是现有模型查看适配，不把它们迁移到像素挤出链                     |
| 后续艺术 3D 模型 / 动画 / 材质 | 在接入相应适配器后统一展示、预览、依赖检查                       | 依类型支持参数/挂点编辑、替换文件或跳转源工具       | 首版不实现 GLB 导入、骨骼、UV 或自由拓扑；不放假示例冒充支持       |

1. 首版物品目录覆盖 `listItemDefinitions()` 当前全部记录；每个物品能展开真实图标、模型、用途与来源。由组合边界提供只读物品元数据，纯资产模块不依赖 server。
2. 内置资产只读；原生像素/挤出资产可复制成独立草稿，支持创建、搜索、筛选、重命名、删除、显式保存。只读类型禁用不支持的操作，并说明原因，不能点“编辑”后无效果。
3. 像素工坊保留 2D 与 3D/手持预览联动；原有图像与模型提供不同的真实预览。贴图 nearest/linear 与平铺是标注清楚的检视对照，不静默改变游戏默认表现。
4. 显式保存到独立 IndexedDB，提供原生像素/挤出草稿包导入导出；失败保留草稿，刷新恢复，切换未保存草稿时提醒。无 WebGL 时仍可访问目录/2D 编辑，并明确 3D 不可用。
5. 木斧、石镐的图标改为同一像素资产的派生产物，手持/掉落/工坊共享源；其余物品保留真实现有资源关系，不能用假映射或错误 fallback 凑全目录。
6. 不支持的类型或缺失的内置资源显示“无法预览/缺失资源”及具体原因。首版导入不认识的类型时整体拒绝并保留原文件，禁止猜测转换或退回木板模型。

## 适配边界

只统一稳定的管理操作，不规定所有资产都必须具有同一套内容字段或编辑器。

- 管理层持有目录、标识、名称、来源、版本、依赖、搜索、选择、脏状态和保存状态。
- 可信的一方适配注册表按类型声明能力：可创建、可编辑内容、可预览 2D/3D/手持、可导出等；UI 根据实际能力呈现操作。
- 每个适配器负责自己的 payload 校验、编辑面板、依赖解释和预览连接，并在需要派生产物时调用共享运行实现。只读引用适配没有虚构的编译和保存步骤。
- 适配器是当前仓库内显式导入的实现，首版不动态安装插件、不执行导入包携带的代码、不设计外部 SDK。
- 游戏与工坊使用同一网格/材质/采样/动作逻辑；工坊仅增加相机、灯光和编辑控件。不同光照、画质和相机不承诺截图逐像素相同。
- 像素挤出“游戏绑定”独立校验：首版两工具白名单，已知 `itemType` 非 block、`placesVoxel` 为空。可放置物拿在手中仍不进入此适配；未知对象不因缺失该字段而自动准入。
- 方块、异形方块和实体艺术模型可归统一资产目录，生产和编辑仍由独立艺术 3D 适配负责。本变更不选择其外部工具或母版格式，不改变已有方块 Chunk Mesh/世界所有权。

## 数据与存储决定

通用信封与类型 payload 分开。取消上一稿在资产包根部限定 `non-placeable-handheld-item` 的设计。

- 信封包含 `schemaVersion: 1` 和记录列表。每条记录有稳定 `id`、`name`、正整数 `revision`、`type`、`source` 和按类型定义的 `payload`。source 区分内置、用户可编辑源和可重建派生来源；依赖由适配器从 payload 解析，公共依赖视图不再存第二份可写真值。
- `generatorVersion` 属于使用生成算法的类型，不要求 PNG 或未来艺术模型也携带像素生成器版本。asset type 与用途独立，不用 item id 当全局 asset id。
- 内置清单是只读资产目录和用途绑定：`itemId → {icon, heldModel, droppedModel}` 等已存在展示角色，每个引用解析到具体资产版本。按 `listItemDefinitions()` 校验覆盖度；特殊图标别名等现有关系必须明确映射，不猜路径。
- IndexedDB 草稿不自动进入游戏绑定；新建模型不等于新建物品、配方或实体。用户包拒绝修改内置清单的字段，未来正式发布另有合同。
- 像素源：width/height、sRGB RGB 调色板、索引像素，索引 0 为透明，最多 64×64、32 色。挤出模型引用 texture id，`thicknessPixels` 为整数总厚度 1–8，grip 为画布内有限像素坐标。
- 挤出 v1：unit=1/16，左上角 `((x-gripX)*unit, (gripY-y)*unit)`，Z 前/后面为 `±thicknessPixels*unit/2`。非透明像素生成前后及暴露侧面，省略邻接内部面；各面使用该像素线性 RGB 顶点色，无 UV 采样。材质 white diffuse、vertex color、gloss=0.12。内置两工具迁移为 16×16、总厚度 2、grip `[7.5,11.5]`。
- 原生草稿包最多 2 MiB、128 条资产；先整体校验 schema、所有 payload、引用、id 唯一性、尺寸与数值，再事务写入。首版不接任意二进制文件或远程资源 URL；未来二进制源由存储适配承载 Blob，不塞入所有类型的像素 JSON。
- 导出模型包含全部像素依赖；导入默认创建新副本并一致重映射 id，不静默覆盖。复制模型默认复制其贴图；共享引用有提示，删除仍被引用的资产时阻止并列出引用方。
- 草稿与保存 revision 分开；同一 IndexedDB 事务内检查预期 revision 并提交，多标签冲突保留草稿、提示重新加载或另存。提交成功后才标记已保存。
- 数据库 `seedlands-asset-workbench` 与世界数据库独立。浏览器配额/禁用存储错误保留草稿并提示导出。IndexedDB 是本浏览器本站点的保存位置，导出是可搬迁备份。
- GPU Mesh/Texture/Entity 不序列化；保存可编辑源或显式源引用，派生产物可重建。资源缓存按 device、asset id/revision、传递依赖版本、适配生成版本和草稿 editRevision 区分；不同标签页不共享 GPU 对象。

## 代码归属与资源生命周期

- `src/client/presentation/`：纯资产结构/校验、原生生成与现有动作计算；不依赖 DOM、PlayCanvas、server 或存储。
- `src/app/gameplay/`：已有工具 GPU 逻辑做窄提取，服务游戏与工坊；其余程序化物品模型通过现有 `GameplayModelAssets.addItem()` 只读适配，不整体重写。
- `src/app/asset-workbench/`：独立页面、管理状态、可信适配器组合、各类型编辑面板与预览场景。不得建立万能 engine/plugins/shared 模块。
- `src/client/persistence/`：工坊的浏览器存储适配；类型校验留在纯模块。先保留清楚的异步边界，未来服务器替换存储适配仍需权限、冲突和发布设计。
- 预览调用共享 `FirstPersonViewmodel` / `viewmodelPose`，同 id 新 revision 不能被现有早退吞掉；先创建新资源、切换引用、释放旧资源，不每帧重建静态模型。
- 异步预览选择采用递增请求版本：旧加载晚到不能覆盖当前选择，过期资源必须释放。类型切换、页面退出、缺失资源和加载失败均有清理路径。
- 构建登记独立入口并更新代码地图，验证生产构建和子路径部署。独立 WebGL 场景复用资源实现，不共享不属于它的 context 对象。
