- `e2e/p0-profiler.ts`：启动独立 headless Chrome，枚举主页面与全部 Dedicated Worker CDP target，对每个 target 采集 1 ms V8 CPU profile 和可用的 heap usage；使用 hidden source map 把采样映射回源码责任。

## 内存与消息/复制开销代理

heap 数据是每个 target 在采样结束时的快照范围，不是峰值、驻留集或前后增量：main used `16.8–43.6 MB`；general `0.8–32.6 MB`；logic `1.0–27.5 MB`；fluid `0.3–1.4 MB`；authority `4.8–17.3 MB`；persistence `1.2–9.7 MB`。完整 total/backing 数值保存在逐运行摘要中。

- 流体 A1/A2 测量窗口提交 `205/210` 个任务、`95,846,400 / 97,320,960` bytes，约 `467,543 / 463,433 bytes/任务`。这包含 fluid 与 general remesh 输入。
- 保存 A1/A2 新增 `5` 个 compute task、`1,474,560` bytes，即 `294,912 bytes/任务`；各有 30 次保存，最终 snapshot 约 `3073/3075 bytes`，storage endpoint `16,483,136 bytes`。
- 加载结束点为 `52` 个任务、`3,538,944` bytes，约 `68,057 bytes/任务`，但没有初始端点，包含完整首次加载。
- 自然负载有任务数量变化，但提交字节计数器未变化；AI 与地图测量窗口无新增 compute task。这个现有计数器不能覆盖所有消息类型。

这些数值是任务消息输入体积代理，不是 structured clone 的 CPU 时间。冻结产物没有独立的 clone CPU、queue wait、输出 bytes 或 transfer detachment 计数，因此均为 `NOT_COLLECTED`，需后续显式 instrumentation 才能测量。
