# 分项与统一 A/B 评测合同

本文是待审核方案的一部分，尚未执行 Wasm 测试。所有数字为拟定实验门槛，不是性能结果，也不加入跨机器的长期基线硬阈值。

## 先定义成本，再决定迁移

一次任务端到端计时：

`T = 输入准备 + 排队/发送 + Worker接收 + 编排/分配 + 输入复制 + 内核 + 输出复制/解包 + 返回/消费`

`净节省 = T_TS - T_Wasm`，`净收益率 = 净节省 / T_TS`。同一Worker原地同步调用没有新增消息往返，但有FFI/工作区成本。现有消息路径的共同成本也不能从用户端计时中删去。冷启动另外计入下载、编译、实例化与首次分配，不能靠预热藏掉。

P0记录每项调用次数/秒、p50/p95、CPU毫秒/秒、输入输出字节数、快照/内核/复制分段、worker角色、队列等待、取消率和GC信息（可观测时）。并行任务用同一发起方时钟测往返；Worker只报告自身区间。跨线程绝对时间线使用 `performance.timeOrigin + performance.now()` 的共同坐标并校准误差；不可直接相减未经校准的各线程 `performance.now()`。

P0先由Playwright的typed fixture附着页面及各Worker的CDP target采集采样profile，再沿热点责任增加相同的有界计时；CDP只作为现有Playwright runner的辅助。原生引擎、GPU和未知堆栈单列，不强行归入TS内核。日志保存各W编号的覆盖状态、未采集原因和剩余未归因CPU比例；若未归因比例超过5%，继续定位后才能冻结清单。

静态≥65分只是预选。进入实现的成本条件是：预估内核节省大于实测新增边界成本的2倍，并且达到下列实际价值门槛之一。预估上界仍不覆盖开销的项目标记“不迁移—复制/粒度不合算”，无需为凑数完整重写。所有通过成本条件的项目必须完成分项A/B；不能只做最容易的一个。

最终分项保留同时要求：

1. 正确性完全通过；包含边界开销的任务p50减少至少15%，配对统计的95%置信区间下界大于0；p95不得出现超过噪声的实质倒退。
2. 批量/事件任务每次净节省至少0.2ms；高频任务也可由稳态至少节省1ms CPU/秒达到价值门槛；一次性启动/地图任务则要求端到端至少节省20ms。W08还要报告自然小规模是否实际获益，不能仅压力场景决定默认启用。
3. 工具链初次建设预算预估不超过2个工程日；普通单项移植与维护测试预估不超过3个工程日。W08若超过5个工程日或需要第二套权威模型则停止该项。超出为低ROI，不用性能倍数掩盖持续双实现成本；这是工作量估算门槛，不是日历承诺。
4. 不引入浏览器/部署能力退化；共享基础设施成本分摊后仍划算。新增下载、编译、内存和首用延迟必须有结果，不能记为0或省略。

复用同一底层数学函数的多个项目不重复记维护成本和CPU节省。门槛附近的结果标记“不确定”，最多追加一轮预注册重复；仍不确定则保留TS。大任务获益、小任务亏损时，可按固定输入规模阈值选择后端，阈值只在开发数据集选定，然后用未参与调参的数据集验证，计入分支与装载成本。不得逐次追着计时结果自适应选择以偏置A/B。

## 试验阶段与控制组

| 阶段   | 比较                                                        | 目的                                        |
| ------ | ----------------------------------------------------------- | ------------------------------------------- |
| P0     | 当前TS不可变产物 A/A                                        | 测自然噪声、全负载分布和边界成本，冻结清单  |
| P1     | MoonBit线性Wasm / WasmGC小型ABI样本；三种内核MoonBit / Rust | 证实能力与语言偏好条件；不作为产品收益      |
| P2     | 每个入选W_i：TS / 仅W_i启用Wasm，其余保持TS                 | 分项真实收益、正确性、规模拐点              |
| P2补充 | 原始TS / 等布局与算法的优化TS / Wasm                        | 将算法、数据布局优化与Wasm本身贡献分开      |
| P2地图 | 当前主线程TS / 相同分片的TS Worker / 相同Worker的Wasm       | 隔离搬离主线程与语言收益                    |

A为本change基准`f245493`，B为冻结的候选提交；预先构建独立产物、独立端口，浏览器读取实际source SHA、入口与Wasm文件hash。A′必须证明后端全关时语义不变、额外开销在噪声内。需要新增埋点时，A/B使用等价仪表，另用原始A复核观察者开销。

## 可复现样本与统计

- 主性能环境为实际 headed Chrome、1920×1080 CSS、Medium，同一机器、供电、DPR、内部渲染分辨率、浏览器版本和显示刷新率；记录而不擅改系统电源/显示设置。独立测试profile，关闭调试可视层，不与其他性能任务并跑。CI/headless只证明可运行和辅助样本。
- 先做6对A/A，估计仪表/温度/调度噪声。每项先固定预热5秒或20个任务取较长者；再采10对AB/BA（平衡顺序，随机种子写入记录），连续场景每个运行30秒。首次运行保持独立冷样本，不丢弃。事件任务每个运行至少30个独立任务；成本过高时先在P0按时长冻结样本数，不能看结果再缩样本。
- 冷启动/首用分别执行10对全新Context，控制HTTP缓存与编译缓存状态并披露能控制的范围。仅新Context不等于清除了浏览器编译缓存；必要时独立浏览器进程。启动门槛含同设备控制网络条件下新增下载成本。
- 报告每次运行的p50/p95/p99、最大值、分布和运行间差异；以“运行”为独立单位做配对bootstrap，保留随机种子及95%CI，不将同一次中的数千帧伪装成独立重复。多项探索结果需在保留数据集和最终组合中复验，不能只报最佳种子/最佳一轮。
- 全部自然样本、异常、失败、取消、超时保留。只按事先定义的环境无效原因（例如测试标签页被隐藏、视口变化）废弃，并保留原记录与原因。错误不是统计离群点。
- 浏览器定时器精度有限：不足分辨率的短函数按自然批量或累计CPU区间测量；不因为追求计时精度打开跨源隔离。内存API不可用时写 `UNSUPPORTED` / `NOT_COLLECTED`；JS heap不能代表Worker/Wasm总内存。

所有整数/字节协议严格相同：无符号溢出、`Math.imul`、逻辑右移、负坐标floor/mod、字节序、varint、半精度打包、字符串ID稳定排序。世界生成最终体素必须完全一致，不能修改generatorVersion规避。

连续浮点采用f64，不启用fast-math；中间纯数值可先用绝对/相对误差`1e-9`定位偏差，但这不是放宽最终行为：每tick离散分支、接触、grounded、路径、fluid和存档必须精确一致；长回放不得累积可见偏差或新增校正。`sin/cos/hypot/round`不一致时优先保留等价数学路径并计入成本，无法满足则该项不迁移。

P3统一场景至少包括：全新进入、静止观察、连续跨Chunk行走、持续挖放、自然河岸流动/消退、16角色+64物件+1024背景水源、AI密集导航、地图切层、批量保存/继续游戏、暂停/恢复/退出重建，以及生成+流体+保存同时发生的竞争场景。初始化可使用生产Harness构造，移动、点击、挖放、跳跃与Pointer Lock通过真实输入覆盖。

功能兼容矩阵必须覆盖Chrome/Chromium、Firefox、WebKit的Wasm启用与强制TS回退：启动、真实输入、编辑、保存/恢复和世界退出重建。实际Safari与Playwright WebKit分别记录，后者不等价于真实Safari设备；未获得真实Safari证据时保留该设备限制。Headless和浏览器引擎兼容检查不作为跨设备性能结论。

## 统一准出与反协同处理

集合B包含所有通过分项门槛的项目，不只选择成绩最好的一项。先完整运行B，即使失败也保留报告；若组合内存、排队或CPU竞争导致反协同，执行去掉单项的消融比较定位，形成B_final后重新与A比较。不得静默去掉失败项后只交最终漂亮数字。

组合有效要求：至少一个预注册关键用户指标（启动、Chunk就绪、编辑至目标revision的postrender、地图完工、保存确认）改善≥10%且CI下界>0，或完整代表场景的CPU总成本下降≥10%且用户延迟无退化。帧p95不得恶化超过`max(0.5ms, A的5%)`，physics step p95不得恶化超过`max(0.1ms, A的5%)`；其余关键延迟不得恶化超过`max(2ms, A的5%)`，并需结合A/A噪声排除环境差异。不得只报告平均FPS。

在上述历史受控负载的同条件复验中继续观察原有frame p95≤20ms、physics p95≤4ms、流体可见p95≤100ms的合同边界；不把这些阈值用于跨机器CI，也不拿它们替代新A/B相对收益。

资源预算：初始工作区按需分配，单实例线性内存硬上限32MiB，所有新增Wasm内存合计≤96MiB；还要计入JS复制缓冲、模块代码、峰值和GC，组合总驻留增量报告出来，不能只满足线性内存。压缩后的新增Wasm和胶水下载目标≤150KiB；首屏额外冷成本不超过`max(50ms, A的5%)`，且普通60秒游玩应覆盖一次性CPU初始化成本。预算不满足则优化/不迁移，增加预算要更新合同。

最终表按场景给出A/B的绝对值、变化百分比、CI、Worker数量、Wasm能力、CPU/内存/下载/冷启动、正确性结果和source SHA。明确“内核快多少”“任务快多少”“玩家看见变化快多少”，允许结论为没有值得合入的Wasm项目。
