## P1：备用水源不在快照中时，撤源清理会误删仍受供水的水格

场景在 `y=5,z=5`：`x=33` 是源，`x=29..32` 是分别为 4、5、6、7 级的流水；下方有固体支撑。权威端同时已有 Chunk `0,0,0` 与 `1,0,0`。撤掉另一个位于 `x=28` 的源后调用 `removeSource([28,5,5])`。

`requestFluidWork()` 只捕获被租赁 frontier 的一跳邻域，因此这个请求仅包含 `0,0,0`。而 `hasAlternateSource()` 执行多跳搜索，实际会尝试越过 `x=31`。未包含的 Chunk 被设置为 `needsRescan=true` 后继续当作没有备用源处理，候选把 `[29,5,5]` 从 4 级水写成空气。供水源依旧存在，这次删除不应发生。

临时只读审查夹具 `/tmp/seedlands-fluid-review.test.ts` 经 Vitest 实际运行得到预期断言失败：

```text
readSet = [{ key: '0,0,0', revision: 0 }]
writes = [{ position: [29,5,5], expectedVoxel: 8,
            expectedFluid: 4, voxel: 0, fluid: 0 }]
needsRescan = true
```

这说明新增“双源”用例不能代替跨边界供水的覆盖。`needsRescan` 也不能撤销已经错误提交的删除和视觉闪变。

## 修订要求

1. 计算读依赖必须与实际算法匹配；一跳快照不足以支持多跳备用源搜索。
2. 搜索因缺数据或预算中断时必须明确区别于“已证明没有供水”，不能直接产生删除。
3. 补充跨 Chunk 双源撤一源的 RED→GREEN，以及跨边界唯一源撤除最终退水、预算耗尽后继续进展的用例。
4. 修复不能通过在 Authority 热路径同步生成 Chunk、无限复制区域或无限图搜索实现。优先审视是否可用局部水位依赖收敛代替额外的全连通清理逻辑；保留显式有界预算与可恢复进展。
