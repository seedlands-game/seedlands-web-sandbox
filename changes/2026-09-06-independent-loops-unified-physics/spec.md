# 独立时钟、多频率循环与统一实体流体物理

状态：待用户审核。流程：Breaking。当前只建立方案；用户批准本文件的精确 SHA-256 后才可实现。

## 背景与目标

基准为 `codex/playable-world-mvp` 的 `622cc23`。当前玩家依渲染帧计算、生物导航直接改位置、非玩家另算竖直重力；上岸使用最多 1.3 格的直接抬升，落地使用中心格判定并叠加脱离重叠补丁。流体虽然 30Hz，但调度由渲染循环驱动，批量编辑与水位侧车不一致，逻辑积压会影响整体时间。

目标是建立一套可验证的运动、碰撞、介质与时间框架，让玩家、生物、掉落物遵守同一几何规则；游戏逻辑掉刻不拖慢物理时钟，渲染独立；客户端与服务端状态所有权明确。完整保留现有可玩 MVP、美术音频和最近倒影修复，停在 AgentServer 接入之前。

## 范围与非目标

纳入：统一物理核心和碰撞形状；重力、接触、连续碰撞、跳搭、快速下落、上岸、浮力阻力与水流作用；稀疏方块流体重构；独立时钟和多频率调度；浏览器内真正隔离的权威 Worker；客户端预测、校正和插值；无 DOM 的同核 headless 适配；旧存档迁移；删除被替代特例和重复计算；完整 SDD 与回归交付。

不纳入：真实多人网络服务、认证和网络基础设施、AgentServer、任意旋转刚体、关节、布料、车辆、复杂堆叠、体积守恒压力流体、海洋波浪、新地形版本、一般物理引擎替换、无证据的性能承诺。网络延迟/乱序只通过受控 transport 验证协议和客户端优化。

## 决策

### 物理引擎与几何模型

本次采用统一的纯 TypeScript 体素物理核心，不引入 Rapier/Ammo。范围限定为平移 AABB 与方块的单个/复合 AABB；碰撞查询直接读取紧凑体素和形状注册表，不生成逐体素渲染 Entity，也不等待可视 Mesh。保留可替换的查询/求解接口，不建设多后端框架。

物理核心包括空间候选查询、扫掠 AABB、首次接触时间、接触法线、滑动和有界重叠恢复。通过移动路径检查高速运动，禁止仅检查终点。并列接触有稳定顺序；数值容差集中定义并测试。重叠恢复仅用于初始化、旧档恢复或明确的外部几何变化，产生可观测原因；正常运动不得靠反复传送纠错。

方块碰撞、角色身体、拾取传感器和交互射线共享坐标/形状描述，语义分别定义。视觉模型不反过来驱动物理；所有实体统一采用脚底中心原点加局部 AABB；身体尺寸、眼睛偏移集中在实体配置，旧位置含义经版本适配。生物按模型体型配置身体，肢体动画不逐帧重建碰撞体。

碰撞矩阵：角色/物件与固体阻挡；角色之间稳定有限推离；掉落物之间允许重叠，合堆为玩法规则；拾取范围是传感器。无需旋转、反弹堆叠和冲量刚体求解。玩家与生物可使用不同运动参数，但不允许不同的几何碰撞算法。

**明确替换旧行为：**取消脚底中心格专判。实际身体底面与固体有有效向上接触才构成支撑；仅接触侧面不算落地。中心格为空但身体仍覆盖邻块时允许站立；所有真实支撑消失才下落。此项会使原中心挖空基线的预期失效，须保留历史记录、由独立 Sol/xhigh 审核新的长期基线语义，不得为测试通过修改真实规则。

一格障碍和一格岸必须跳跃。Space 在地面触发起跳，在水中表达上浮/水面跃出意图；允许显式的水面起跳速度规则，但不直接修改高度。向上途中有空间、脚底实际越过岸顶后才可横向登岸。禁用一格自动爬阶、向上寻空、远距离贴地和下台阶强制吸附。跳搭按真实按键和编辑事务驱动，不能因中心格/四角规则悬空。

### 真实碰撞箱调试显示

增加 `F3+B` 开关，并在调试面板提供等价开关；组合键完整消费，不能同时触发普通 F3 面板切换或 B 的其他操作。默认关闭，只在调试界面启用，不改变世界、物理或存档。

默认以批量线框显示附近玩家、生物、掉落物的真实身体碰撞形状，以及瞄准方块的实际子碰撞箱（例如灯笼），不使用渲染模型包围盒、选择轮廓或额外手画的近似尺寸。几何来自物理核心的同一注册表/只读调试投影；标注状态来源和 tick。服务端已确认状态与本地玩家预测状态使用不同颜色和图例，不能把两个时刻的形状误认为同一个“真实位置”。默认实体范围 32 格、最多 128 个身体；方块细节只显示当前目标及可选的近场接触形状，截断时显示计数。

接触点、接触法线和支撑状态作为调试面板可选细节，拾取传感器与身体碰撞箱明确区分。调试层不进入阴影、倒影和游戏交互；关闭后停止额外调试快照请求、线框构建和绘制，释放相应资源，不每帧创建逐方块 Entity。

### 四种时间与多频率调度

1. 单调真实时间：各执行环境用单调时钟测量经过时间，经初始化握手建立可比较的会话时间；不能假定不同 Worker 的 `performance.now()` 原点相同。
2. 活跃游玩时间：真实时间扣除显式暂停区间。昼夜、具有经过时间语义的冷却和需求使用该时间/截止时间；不能由完成了多少游戏 tick 决定时间是否流逝。昼夜倍率只改变昼夜，不隐式改变物理。
3. 物理已积分时间：固定步长累计，只在实际求解后推进；另记目标物理时间和积压。游戏逻辑落后不改变物理目标时间。绝不以跳过碰撞积分或传送来假装物理跟上时钟。
4. 表现时间：渲染插值、UI、音频和非权威动画使用各自适当的时间，不能反向改变状态。

默认物理 60Hz、游戏调度 20Hz、流体目标 30Hz；生物意图跟进可 10Hz、感知/决策 1–2Hz。频率原生可配置，使用独立 deadline/累加器，不依赖渲染帧数或整数倍假设；测试组合包括物理 30/60/120、逻辑 10/20、流体 20/30Hz。频率配置在会话启动时握手，运行中切频需明确重建边界，不要求无缝热切换。

游戏逻辑可以合并/丢弃过期的 AI 思考和表现请求，延迟可重新验证的计算；输入、编辑、库存、伤害、拾取、保存不能静默丢弃。关键事务按命令序号执行一次，过期状态校验失败返回明确结果。攻击过期不对过去位置补伤害，需求按截止时间累计，AI 不补跑无限次旧思考。

物理每次唤醒有有限追赶步数；不传巨大 dt，不让不同系统各自清零时间。持续物理过载允许明确整体减速/降低非关键任务预算并报告债务；无法保证 CPU 耗尽、系统睡眠或浏览器节流下的硬实时。浏览器单人模式失焦/隐藏按统一暂停协议处理，清空按键状态；恢复重置唤醒基准，不补算睡眠时间。

### 实际线程和所有权

- 主线程：PlayCanvas 渲染、输入、UI、音频和本地玩家预测；不拥有权威世界、位置、库存或流体，不运行全世界物理和 AI。
- 专用权威/物理 Worker：唯一写入权威世界、实体位置/速度/接触、库存和世界版本；独立运行物理调度。必要的命令验证、原子编辑、伤害和拾取提交为短有界阶段。不得运行 Mesh、同步世界生成、无界寻路或长 AI。
- 游戏逻辑 Worker：独立调度决策和意图，只消费快照并提出命令/计划，不直接改实体坐标、库存或体素。逻辑停顿时物理使用最近有效且未过期的控制意图；停止/释放输入走权威输入通道，不被逻辑队列挡住。
- 计算 Worker 池：按优先级运行流体传播候选、Chunk 生成、网格和导航等有界任务；流体初版保留一个独立 Worker/计算槽位（不与游戏逻辑或 Mesh 共享无保留 FIFO）；其他任务采用独立队列、配额、老化和任务切片防止 Mesh 独占。只返回派生结果，由权威所有者验证后接纳。按当前 Mac 从少量 Worker 起步，以采样选择容量，不以线程数验收。

专用权威 Worker 是有状态所有权边界；计算池是可并行资源，不按每个业务永久占一条线程。初期通过 transferable 数值快照/增量传递，禁止逐帧复制全世界，不引入 SharedArrayBuffer/WASM threads 或跨源隔离部署要求。

`World.edit()` 与 `GameServer.editBatch()` 的语义边界保留，经异步命令适配访问。物理查询只读已接纳的近场权威碰撞数据；未加载区域使用显式阻挡/等待策略，不视为空气、不在物理回调内同步生成世界。跨 Chunk 数据按版本成组提交，防止半更新边界。

### Worker 池关系与全局并发成本

统一的 Worker 管理器管理线程生命周期、预算、队列和指标；专用 Worker 不等于计算池任务槽位。权威物理和游戏逻辑各有一个独立执行环境，固定状态所有权；计算池接收流体、生成、网格、导航等派生计算任务。流体占池内保留槽位，其余通用槽位轮流处理不同任务，不为每种业务再开一个永久 Worker。现有世界生成/网格 Worker 被池替换，不能保留旧实例再叠加新池。

当前 Mac 实测 12 个逻辑处理器。初始计算池为 2 个 Worker（流体保留 1、通用 1），以同机 A/A、A/B 对比 3 个 Worker（流体 1、通用 2）；当前合同计算池硬上限 3。加权威 1、游戏逻辑 1、既有持久化 Worker 最多 1，总后台 Worker 上限 6（不含浏览器/引擎内部线程）。持久化虽多数等待 I/O，也计入实例/内存预算；池的任务 CPU 并发上限与实例上限分开统计。不得依据12核直接开12个繁忙 Worker，也不能宣称浏览器能绑定或独占某颗核心。

`navigator.hardwareConcurrency` 仅为可用并行度提示，浏览器可能低报；实际容量取保守配置与测量结果，不以同一个公式适用于所有设备。低资源环境缩小通用池、视距和背景任务预算，不能默默把物理频率绑到画质或渲染帧率。初版不做频繁的自动增删 Worker；稳定样本证明收益后，在会话边界选择池容量。

并发治理必须同时覆盖：

- 任务调度：每 Worker 同时最多一个 CPU 任务；依赖用 DAG/就绪队列表达（生成后网格），未满足依赖不占工作槽。流体保留容量不能被长 Mesh 占用，初版不借给长任务。
- 优先级与公平：近场碰撞数据/交互反馈优先；后台 streaming 和远景采用配额与老化，不让持续近场编辑永久饿死其他任务。队列按任务类型限制数量和总字节；上游超限时背压/合并，关键命令明确排队或拒绝，不能静默丢弃。
- 合并与取消：同 Chunk 的重复 remesh 合并为最新需求；同版本去重。取消未开始任务；执行中任务在安全切片点合作式取消。标记结果过期不等于停止 CPU 计算，二者分开计量。长网格/生成任务必须评估单 Chunk 最坏耗时，必要时继续按扫描阶段切片。
- 数据成本：传增量或局部快照，使用 transferable 的专用缓冲区并有界复用；不 transfer 唯一权威数组导致其被 detach。统计复制/序列化耗时、传输字节、池内缓存和排队数据，不以“transferable”宣称全链路零拷贝。
- 主线程与权威提交：Worker 算得更快时，结果仍受主线程 GPU 上传预算和权威事务预算约束；下游积压反压上游，不能靠无限预计算堆内存。
- 自适应与退出：以物理 deadline miss、frame p95、任务等待 p95、过期计算比例、上传队列和内存为反馈，优先减少远景/后台派发。额外 Worker 没有净收益则退回较小池。切换世界先取消 epoch，结束或回收在途任务，不能出现残留线程和旧世界提交。

运行时 Web Worker 消耗本机 CPU、内存、电量与传输成本，不消耗模型 token。开发期间 Sol/Terra 的并行任务使用单独的额度预算和协作槽位，不与游戏 Worker 数量混算。

### 流体与介质

保留有界方块源水/流量等级规则、向下优先、横向扩散、源水撤除及活动窗口暂停；自然水源可持续供水，不宣称水量守恒。

权威 Worker 持有水位、源标记、活动队列/边界和版本；计算池从带版本的有限区域快照计算一个有预算的传播步，返回候选 delta 和下一队列。初版全局只允许一个在途流体任务，后续区域并行不属于本次准出要求。Authority 租赁一小批 frontier，候选带 workId、逐 Chunk 的 contentRevision 读集、预期旧 cell、写集、已消费及新增 frontier。有序原子提交，每个受影响 Chunk 只推进一次 revision；在物理步边界接纳后，下一物理步读取新状态。验证读集、写集、边界版本和会话 epoch，不能只比较全局 revision，不能把不同 revision 混成一个流体步。

过期结果拒绝或 Worker 故障后，租赁 frontier 原样归还，再合并最新修改并重算，不无限丢弃老任务造成饥饿；每次物理步保留有条数/耗时上限的候选提交窗口，多余候选延后；流体不得因完成计算前等待而阻塞物理。队列满时记录区域需要重扫，空闲后恢复，不能遗失传播工作。活动流体只反映已经提交的水位，帧显示延迟和求解积压分别统计。交互编辑优先，持续热点采用区域串行、合并和有限重算策略，无法稳定提交时显式降速而非无声无限重试。

逐格、批量、缓冲区编辑、源水删除、恢复和边界激活复用同一流体事务逻辑；修复侧车遗漏与撤源差异。网格高度、反射面、身体介质和眼睛入水使用同一水面定义。

所有实体按身体与水体的实际重叠采样浸没比例，计算重力、浮力、相对流速阻力；眼睛入水另有小范围滞回驱动画面/声音。浮沉参数按物品/角色配置。流体提交产生有定义的水平/竖直流向及强度，实体受力不复用纯视觉的宏观河流方向。静水不施加伪造河流推力。

水面表现与权威流体分离：纹理运动每帧连续，液面/边界过渡基于相邻已提交状态；移除用整块新旧 Mesh 透明度叠加冒充流动的路径。新水体的可见延迟由完整链路测量，不能仅凭 30Hz 或开启动画宣称即时响应。保留本轮世界位置倒影修复。

### 客户端、服务端与保存

定义 DOM-free 的输入命令、事务回执、带 tick/revision 的快照和事件协议。每个会话有 epoch；输入有 sequence、目标物理 tick、按键边沿和持续状态；快照带 ack、physicsTick 和 commitSeq，旧会话、乱序和重复消息不得重复生效。客户端碰撞缓存与预测历史必须记录对应 Chunk revision；缺少历史碰撞版本时停止旧状态重放并重同步，不能用新地形假装重放旧输入。

本地玩家复用同一纯物理核心，在近场碰撞缓存预测；权威快照到达后回退并重放未确认输入。只预测本地玩家与可撤销表现，不预测库存入账、掉落生成或权威水位。镜头旋转即时响应；位置的小误差只平滑表现，权威碰撞立即校正，不能通过墙体 lerp；大误差使用明确恢复路径并记录原因。

其他实体用有时间戳的快照插值，有限外推与超时停止；禁止平滑器替代真实物理。客户端必须能展示缺失数据、同步中和 Worker 故障，不能静默退回旧的全主线程权威架构。

无 DOM 的本地 headless transport 使用相同调度和协议，支持分别推进物理/逻辑/流体及推进整个会话；旧 `/tick` 的含义明确迁移并更新操作说明。真实网络适配只留接口，不部署多人服务。

存档保留 seed/generatorVersion/体素 ID，物理状态及坐标版本明确迁移；旧档保留原始数据，迁移失败拒绝进入并给出原因。冻结权威版本后保存一致快照，确认持久化完成才返回成功，不因逻辑 Worker 落后而丢库存或已提交编辑。不直接覆盖用户正在玩的存档做测试。

### 静态边界

拟新增 `src/physics/` 和 `src/runtime/` 的纯逻辑核心：不依赖 DOM、PlayCanvas、Worker global 或浏览器存储。`src/worker/` 仅做执行环境与传输接线，`src/client/` 保存预测/同步适配，`src/server/` 保存权威规则。`src/world/` 既有单向依赖保持。

实现前先增加边界规则的正反例测试，再落模块；限制模块大小，禁止新建替代旧单体的大文件。只有局部玩家预测是明确允许的重复计算；整个世界和全体实体不得在客户端与服务端各算一遍。

## 行为

- 同一时间戳输入，渲染帧率 30/60/120 或逻辑 Worker 停顿，不改变物理调度来源。按下/松开与失焦不会粘键。
- 空中快速下落经过薄平台仍碰撞；头顶、侧面、角落、灯笼形状统一处理，不依赖先卡进方块再修正。
- 连续跳搭和连续向下挖掘按真实支撑判定；无支撑不得悬空，仍有真实接触不得凭中心格空强制穿过邻块。
- 一格岸需前进加跳跃；完整轨迹有净空才成功，低顶不能穿越，离水浮力/阻力连续改变。
- AI 只输出移动/跳跃意图，生物不能走路径时直接插值到上一格，也不能覆盖重力结果。
- 未加载碰撞区阻挡继续移动并触发加载；Mesh 晚到不改变已经提交的碰撞规则。
- 水位、侧车、介质、反射面和可见网格有一致版本边界；迟到流体任务不得覆盖玩家刚放的障碍。
