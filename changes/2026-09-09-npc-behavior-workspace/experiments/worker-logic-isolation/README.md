# 主线程隔离功能对照

目的：验证渲染主线程调度不会阻止已绑定角色的正常身体动作；不声称CPU、内存或吞吐收益。

控制版本1a2cfd8，固定种子npc-continuous-life-v1、同一树和256单位初始食物、无模型与后续资源注入。新增测试只施加30次主线程300ms忙循环和10ms让出。控制的9.3594秒模拟推进中物理tick14→576，而NPC只移动0.44米，饥饿60→61，未拾取或完成补给，重规划9次。原始trace与精简状态见control.json。

候选只更换Authority/Logic之间的浏览器通信路径，使用MessageChannel直接转发既有观察/意图合同，保留200ms新鲜度及权威接纳校验。相同阻塞负载应完成正常拾取、消耗、补给终态。其他准出包括单inflight、最新pending、旧epoch/乱序拒绝、派生buffer转移、端口释放、确定性快进及回档。首版候选在相同浏览器/开发服务/阻塞条件下GREEN，9.3519秒模拟时间内完成一次补给，普通补给场景也通过（两项共23.8秒）。精简证据见candidate-first.json。最终生命周期修正后的组合复验仍待执行。

补充诊断：同一开发服务及basepath在system Chrome和full Chromium中两项生活测试通过（46.9/56.7秒，普通功能测试计时）；headless shell短测通过，但三昼夜240秒期限仅完成570模拟秒/6次补给后中止。该失败证明宿主差异需要覆盖，不用于推导浏览器或CPU性能结论。

独立的Headless检查：调整宿主期限后的覆盖率插桩定向运行七项行为断言全部通过，测试体78.11秒。由于只选择该文件，整体world行覆盖率57.51%而全仓门槛80%，命令按门槛退出1；不能记作完整coverage门禁通过。最终全量coverage另行执行。
