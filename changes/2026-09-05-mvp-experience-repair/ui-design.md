# UI还原设计与实现前语义预期

所附原型是唯一视觉目标。游戏视野仍为全屏，快捷栏固定八槽；将图标生命/饥饿与快捷栏放入同一宽度的底部居中流式容器，消除原独立左下状态和超宽快捷栏交叠。

- Given 1920×1080/1280×720/700px宽，When 进入世界，Then 8槽均可見，每格只显示三维缩略图、数量、数字键；选中黄铜高亮，物品名称在栏上方小行显示。生命、饥饿各10图标，2点/格，可显示半格，有真实可读meter语义。两组排在栏上方同一行，窄窗缩小间距而不溢出。
- Given 准星瞄准可达方块，When 目标变化，Then 顶部居中黑曜石黄铜信息框显示相同方块贴图、名称和采集进度；没有目标/超距隐藏。时钟移至顶部左侧避免相交。正常HUD隐藏实体调试标签，F3可见。
- Given 暂停/设置/菜单，When 打开，Then 细金属边框、统一青色主按钮、暗纹次级按钮、宝石纹章及层次一致；尺寸适合内容，暂停不是一块巨大平板。所有正文对比充分，所有操作有hover/focus/pressed态。暂停隐藏背后手持HUD避免竞争，世界保留可辨背景。
- Given 声音已用户验收，When 仅改视觉，Then 音量操作/音乐状态逻辑保持，仍可本地导入。

证据：先写需求级presentation.spec.ts预期RED（现有状态区与快捷栏相交，手持是SVG，正常模式实体标签可见，暂停无纹章），随后真实浏览器尺寸断言+保存截图；Midscene按原型逐项判断材料、组成、比例、层级，不用存在断言替代还原。

调试口径修正：F3 中 `Materialized Chunks` 目前绑定 `world.mutationCount`，标题误导了容量复核。改为真实含义 `World Mutations`；Given 世界编辑，Then 此计数增加且标签不再声称是 Chunk 数。该文案按 Static/Build 与最终 F3 截图确认，不引入新性能指标或基线。

证据目录静态规则：全量静态在新增 `changes/<日期>/evidence/` 处 RED，因为父 `changes/*` 的日期目录规则被继承到证据子目录。按现有 `midscene`/`e2e` 同层规则补充 `changes/*/evidence` 的 kebab-case 命名规则，保留 change 根日期格式；不忽略证据目录。Acceptance：`pnpm lint:paths` GREEN。

### Midscene 视觉 RED 后槽框修订

P1-视觉-01：实际正常 HUD 槽位边框过于平直、颜色近白，无法辨认原型的黄铜角饰与黑曜石材质。采用单独生成的正方形槽框 bitmap，直接铺满每个槽位，保留中央深色纹理与较粗但克制的金属角饰；选中态增加暖金发光，名称/数量/键位仍为可读 DOM。Given 正常游玩，Then 8槽轮廓应直接可见黄铜四角、深色材质而非普通白线方框。该修订以原型并排 Midscene 复验，不降低原视觉合同。

14:48 新 bitmap 后仍出现材料语义 RED。比例复核：旧560px上限在1920画面仅占29%，原型的槽框与状态有更高视觉权重。改为按正方形槽尺寸计算栏宽（桌面约750px，窄窗随视口缩小），放大心/肉图标；对应第一人称持握按相机宽高比锚定右侧，给快捷栏留出空间。Given 1280/1920/700三尺寸，Then 方格维持接近正方、金属角饰清楚、手与HUD不交叠，最终仍由尺寸E2E与原型Midscene判定，不删除旧RED。

## 15:04 目标卡片视觉 RED 后修订

实时 Midscene 已通过 HUD/持握，但目标卡片只识别出深底和白字，未识别材料层次。根捕获实际 1920×1080 帧确认：186px 小卡片有黄铜细边，但空闲态无青宝石强调，名称与图标偏弱。因此在同一目标卡片内使用已有青宝石纹章、增大图标与字级/边框可辨性，保持顶部、小型卡片和同源目标数据。Given 可达泥土，When 空闲/采集，Then 深石纹、黄铜角饰、青宝石与方块缩略图可辨且不压准星；对应原 live Midscene 材料断言复验，不删该断言来通过。
