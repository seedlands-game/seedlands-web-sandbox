# 模糊需求澄清基础规范

## Goal

把“用户意图优先、技术提议待验证”“成熟能力优先、最低成本验证”和“所有优化独立分项 A/B、短板与用户指标优先”纳入 Seedlands 轻量 SDD，防止智能体迎合技术猜测、提前自建或用局部加速冒充有效优化。

## Scope

- 在 `docs/development-governance.md` 定义意图、愿景、硬约束、技术假设和未知项的分离方式。
- 建立现状读取、社区/行业一手资料核对、主动反驳与方案推荐的责任。
- 建立复用 → 接入/购买 → 有界改造 → 自建的候选顺序，以及按剩余总成本决策的门禁。
- 定义最小纵向验证切片、自建例外、失败模式和澄清完成条件。
- 在 `AGENTS.md` 增加开工即见的短规则，并链接完整规范。
- 全量索引既有 change，以带基线 commit 和纳入/排除清单的 manifest 回收性能、效率、测量与技术选型经验，另行核对 Node 独立服务端网络选型分支。
- 定义优化触发条件、独立分项 A/B、证据层级、组合消融、负结果处置和重新验证条件。
- 在 `docs/performance-execution.md` 明确资源预约不替代 A/B 合同。

## Non-goals

- 不为当前产品路线重新选型，不决定是否迁移体素引擎、渲染引擎或服务端架构。
- 不规定所有需求都必须联网调研；已有证据足够时只读取项目现状，时效性候选结论才要求 live check。
- 不把“造不如买”简化为总是采购 SaaS、选择 stars 最多的项目，或忽略已有自研资产和迁移成本。
- 不修改已 Delivered 的历史 change 合同，不创建产品代码、原型或新的依赖。
- 不重新裁决既有 Wasm、渲染、网络或 Node 方案，不重跑历史性能实验。

## Decisions

1. 用户对意图与最终取舍负责；用户的技术提议和智能体的技术提议采用相同证据门槛，默认均为可证伪假设。
2. 澄清者不能把技术判断退还给门外汉用户。必须结合长期愿景、当前实现、一手资料和成本，明确推荐一条路径，并解释反对其他路径的理由。
3. 默认优先复用现有能力与成熟基础设施。选择自建必须记录候选排除证据或总成本优势，不能只用控制感、技术新颖度或未来可能性证明。
4. 决策主口径是从当前状态到下一个可验证体验的剩余总成本，包括适配、迁移、运行、维护、退出和验证，而不是沉没成本或功能表。
5. 先用最小代表性切片消除会改变决策的未知；不预建完整迁移、平台抽象或更多底层能力来回避价值验证。
6. 调研深度与影响面和决策价值成比例；小型局部歧义不要求全仓、全市场穷举，不适用维度可以记录 `N/A` 和理由。
7. 任何优化或“技术更优”的采纳声明都需要独立分项 A/B；诊断、微基准、组件和端到端证据分层解释，不能相互替代。
8. 未触碰已测瓶颈、产品门槛、用户问题或可证明的规模硬上限时不提前优化；候选优先级由瓶颈贡献、频率、用户影响与剩余总成本共同决定。
9. 分项候选一次只改变一个实验轴，计时实验先 A/A 校准噪声，再做除预注册轴外身份一致的平衡/交错 A/B；计划共存且影响同一路径的通过项必须再接受组合端到端 A/B，组合回归时按预注册上限消融或撤回。
10. 没有确定收益时保留更简单的 control。负结果是有效交付，不能换指标、挑样本或把 fallback 冒充候选；未采用生产路径应移除并保留重开条件。

## Behaviour

- Given 用户表达核心体验，同时猜测必须使用某项技术，When 进入模糊需求澄清，Then 记录核心体验为意图、记录技术选择为待验证假设，并检查是否存在明确硬约束或既有决策使它成为约束。
- Given 用户并不具备该领域的专业判断，When 多个技术选项存在，Then 智能体读取项目现状和仍然有效的一手资料，指出错误前提，并给出带理由的推荐，而不是只复述或要求用户凭直觉选技术。
- Given 社区或现有依赖中存在成熟候选，When 方案比较，Then 先评估复用、薄接入和有界改造；若仍推荐自建，必须记录候选不满足的硬约束或更高剩余总成本证据。
- Given 候选信息具有时效性，When 声称其可用、不可用、成熟或不兼容，Then 必须 live check 并保留来源与验证边界；未核对项标为未知。
- Given 方向仍有关键未知，When 选择下一步，Then 先执行能改变决策的最小只读调研或可丢弃实验；不先实施完整平台、迁移或通用抽象。
- Given 新证据推翻先前技术方案，When 更新 spec，Then 保留用户意图并重新比较路径，不以沉没成本或维护旧结论为由拒绝修正。
- Given 只是小型局部歧义，When 现有相关路径和真正会改变决定的候选已足以作出可逆选择，Then 停止扩展调研；不要求穷举仓库或市场，不适用维度记录为 `N/A`。
- Given 没有 profile、用户问题、产品预算或规模硬上限证明某路径是短板，When Agent 提议预先优化，Then 记录观察项并停止实现，不以未来可能性或技术新颖度立项。
- Given 同一 change 有多个优化候选，When 建立实验，Then 每项独立固定 A/B、主/次指标、否决项与停止线，先 A/A 校准后再按相同身份和负载交错采样。
- Given kernel 或分项指标改善，When 决定进入默认生产路径，Then 还必须通过含准备、复制、排队、回传和真实用户主指标的组合端到端 A/B；组合回归则有界消融或撤回。
- Given A/B 无确定收益、低于计时分辨率、发生 fallback 或触发否决项，When 交付，Then 分别记录中性/未知/失败边界，保留更简单 control，不换指标或挑选 GREEN。
- Given 技术选型同时改变语义、codec、传输、频率或并发，When 解释收益，Then 拆成独立实验轴或声明不可分割单元，不把整组变化归给单个技术名称。
- Given 旧 control 因安全、许可证、平台弃用或硬兼容约束不可安全运行，When 选择替代方案，Then 可用一手公告和静态合同淘汰 A，但不宣称未对照的运行时收益。
