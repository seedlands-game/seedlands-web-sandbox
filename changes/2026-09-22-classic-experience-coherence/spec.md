状态：Active，当前阶段实现已停止扩展，按用户要求提交并 push；最终实机验收与缩略图派生未完成，见 delivery-snapshot.md。

## 授权与目标

用户要求继续已批准的 Classic 老 Minecraft 几何与较低饱和像素视觉；亲自观察真实游戏，与预期差距按系统问题统一修复，不只修截图单点。用户明确要求执行交给便宜 worker、UI 动作由 Jev 优先选择并经 Cua 执行/录制，主 agent 统筹与审看；不运行端到端测试，不因中间技术困难重复询问确认。该当轮指令优先于本地重复 hash 确认流程，仅覆盖本次体验修复，不扩大权限、发布或外部写入范围。Blender 若确有需要仍只交 Astra。

需求：玩家看到协调、清晰、可辨认的 Classic 场景，并能通过一致的菜单、背包和 HUD 进入基础采集/制作/建造过程。现象只是检索入口：蘑菇方片要追查所有透明植物；夜行兽错误要追查全部退役角色引用；一个巨大目录卡片要追查共享 UI 尺度与信息层级。

技术假设（待证伪）：世界植物与物品图标使用了不同来源/映射；默认植物尺寸与调色缺少统一约束；退役角色只过滤权威状态而未清理开发体验入口；进入失败未完整撤销呈现状态；UI 通用像素边框被等比叠加到密集槽位。以源码审计修正，不把假设当结论。

## 范围与硬边界

1. 透明植物/世界材质/物品图标的来源、映射、alpha、轮廓与尺度；覆盖整类资产，不仅红蘑菇。
2. 活跃入口/帮助/失败生命周期与 Classic 退役内容的一致性；迁移过滤与合法旧存档兼容保留。
3. HUD、库存/创造目录、配方呈现的共用比例、稳定布局和信息层级；复用现有合成与选择能力。
4. 在同一可玩场景审看修复后的组合效果，不以独立图标预览替代实际世界表现。

不实现 Modern、不更换渲染后端、不引入 PBR、不扩大游戏内 Agent 权限、不改变存档格式。不为减少视觉密度偷偷删除/隐藏可交互世界块；若根因要求更改生成算法，必须保持 `seed + generatorVersion` 确定性与旧版本兼容，单独列出确切版本方案后实施。保护无关 hotpath 优化目录及其独立工作树。

## 行为与验收

- Given 注册的每种透明植物，When 它出现在世界、目录与掉落等既有显示面，Then 都使用可识别的同类轮廓/色彩，透明背景不变成满矩形；碰撞/采集语义不因外观改变。
- Given Classic 已退役三种自定义角色，When 玩家使用任何活跃第一方入口，Then 不请求不存在的角色；加载失败必须回到单一、可恢复的菜单状态。
- Given 玩家空手进入生存，When 打开背包，Then 基础配方路径与实际能力清楚，信息按玩家任务组织。
- Given 创造目录搜索/选物，When 切换结果，Then 搜索与关闭入口位置稳定，紧凑槽位优先显示辨认信息，内部 ID 不占常规界面。
- Given 普通探索画面，Then 常驻 HUD 不用重复边框/攻击待机文字压过世界；选中、受击、攻击过程的有效反馈仍保留。

RED 使用上面的可复查实际观察；实施前补必要确定性失败断言。GREEN 按 owner 的已有静态/纯逻辑检查与 Cua/Jev 回看分层记录。本轮不启动 E2E/Playwright，不修改远端 CI 门禁。重型 build/test/browser 一律由 `node scripts/benchmark-window.mjs -- <command>` 取得默认共享锁；不手动删锁，不宣称性能收益。

## 分工与状态

源码审计确定：体验场仍请求 `night-stalker`，而当前 Classic 未注册它；`abortStart` 缺少正常离开路径的 HUD 收束。创造目录缺少稳定视口、常显内部 ID；快捷栏外观存在重复级联；配方按注册序显示；工具采用统一偏大缩放。植物外观存在两条资源来源，但“旧覆盖导致异常”尚未证实，不以此为由重置用户资源。当前 `plantPixel()` 的 `(x+y)%5` 白斑可产生对角重复图样，必须结合真实截图审查完整轮廓，而非仅断言 cutout 配置通过。
