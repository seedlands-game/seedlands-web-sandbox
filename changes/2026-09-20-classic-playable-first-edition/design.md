# 完整初版实施设计

## 意图与技术选择

| 类别 | 决定                                                                |
| ---- | ------------------------------------------------------------------- |
| 结果 | Seedlands 上的早期 Minecraft 单人生存，可持续保存并体验所有纳入内容 |
| 愿景 | 以复杂 Playbook 验证小内核和标准模块，服务 Living World             |
| 约束 | WebGL2/Chunk Mesh、单权威、World.edit、版本化保存、原创资源、低干扰 |
| 假设 | 现有机制可复用；具体扩展由真实消费者推动                            |
| 未知 | 原版精确随机/更新次序、主观音画和实体设备性能，留下对照账           |

现有 stdlib 已有挖放/库存/工位/战斗/需求/水/光/导航/保存，Classic 显式组装，Web 表现。复用并扩展这些调用面。EaglerPorts 是 Java/TeaVM 完整运行时，嵌入会另建权威；购买托管 Minecraft 也不能验证自己的引擎。全部重写会重复现有事务和 Worker，因此采用增量扩展。

## 状态与接口

- 内容：Classic 拥有定义、数值、referenceId 与原创资源映射。追加稳定数字 ID；复杂变体显式编码，保存版本固定。
- 方块：stdlib 拥有形状/朝向/AABB/透光/替换/邻居更新；Uint16 体素加位置绑定稀疏组件保存容器/牌/床。复合放置一次合法候选提交，失败不扣物品。
- 调度：权威时钟、seed 派生 RNG、计划 tick 与 random tick 分开；稳定顺序/队列进 checkpoint，未加载邻域延迟处理。
- 物品：place/consume/mine/melee 按消费者扩展 health food、use-on-block、projectile、equipment；定义和执行器一起交付，UI 只发意图。
- 生命：关闭玩家 hunger 推进；consume 选择 healthRestore 或 hungerRestore，库存与生命原子提交，NPC needs 独立。护甲/伤害源经 combat owner。
- 库存：36 格、9 快捷栏、独立装备；2×2/3×3 匹配、镜像/余物/满格拒绝。单/双箱、炉、唱片机有独立状态，游标进 checkpoint。
- 环境：水/熔岩 kind/level/source 与更新候选；混合产物经 World.edit。火/爆炸、天气、作物/叶衰减是可选 stdlib 模块，Classic 定义规则。
- 实体：复用 ECS 身份/位置/碰撞/生命；物种 profile 与行为组合，不能只改名字；掉落走 world-item，刷怪有光/距离/上限。
- 运输：载具拥有乘坐引用、速度与轨道/水状态；上下车校验占用/安全点，不建第二位置权威；轨道连接和车辆分开。
- 世界：新生成版本保留旧版入口，seed/坐标决定地形/洞穴/矿物/植被/地牢。精确 Java 算法差异留账，同 Seedlands 版本必须确定。
- 表现：扩展 PlayCanvas Chunk Mesh、Svelte、atlas、第一人称和音频总线；原创轮廓区分实体，缺资产不能叫视觉完成。
- 保存：同一 frontier 捕获地形/方块状态/actors/tick/RNG/库存游标/天气时间，重开逐值核对；不做离线追赶，未知 schema 替换前拒绝。

## 旅程

P0：独立存储、seed、空库存、安全出生、真实输入。
P1：木材→木板/木棍→工作台→木/石工具→煤铁→炉/箱→铁器→庇护；缺料/越距/耐久负例。
P2：刷怪/庇护/近战弓/伤害食物/死亡掉落/床重生。
P3：流体混合、火/TNT、天气/光、作物树木与邻域变化。
P4：钓鱼驯服剪毛染色、地图时钟指南针、牌画唱片、矿车船。
P5：半程冶炼、容器游标、种植火实体载具保存，同源重开继续，无丢失复制。

规则由确定性测试证明，键鼠由唯一 E2E 证明；视觉保留多帧。静音只验证音频事件/资源，主观听感未验证。性能另行独占 A/A/A/B。

## S1 库存实施合同

Classic 通过 defineInventoryModule 的明确 playerLayout 配置选择 36/9；标准库默认与 NPC 保持 24/8。布局为每世界冻结数据，进入 composition capability identity，ECS owner 初始化和保存校验消费同一配置。历史 24/8 保存形状仍可解析，不静默丢槽；产品旧 Pack 身份仍由原 checkpoint guard 决定是否接受，不扩大未知存档准入。UI 读取实际 player.hotbarSize/inventory.length，禁止固定截断。9 键选择、最后一格移动/消耗、模式切换与重开保存必须测试。新增状态不进 Kernel。

S1 食物：healthRestore 是可选消费能力，旧 hungerRestore 兼容；正式操作的只读 vitals 进入 candidate，提交前重新求值，生命和物品使用同一次 prepared actor mutation。Classic 关闭 satiety 自动推进且浆果临时按 4 点恢复；浆果并非 b1.7.3 原版食物，后续苹果/面包/肉/鱼等内容完成时明确替换与映射，此时不宣称全量 parity。

## S1 木板建造合同

追加稳定 Voxel.Planks=16 / FaceMaterial.Planks=19，不更改 0–15/1–18 身份或 generatorVersion。现有 plank 物品改为可放置全立方体；木板可徒手挖回 1 个 plank，斧加速。TS/Rust 网格和 Web 材质层共同支持追加 ID，采用原创横向木板纹理。正式生存操作扣库存，存档保存木板编辑与库存；恢复后再挖回，数量守恒。低层 palette/mesh、正式 Authority 成长/存档与同一浏览器线路分别取证；旧 ID、未知 ID 拒绝继续验证。

RED：当前 plank 没有 place capability；新增从 1 原木合成 4 木板、放置一个并恢复后挖回的正式操作测试，现状应在 place 失败。新增 TS 单立方体材料测试现状缺少材料 19。

## S1 木棍与工具材料

新增 stick 物品，2 木板→4 木棍（材料守恒）。现有木斧/木剑/石镐快捷合成及工作台木/石/铁镐统一使用木棍作柄：斧与镐需要 2 木棍，剑需要 1 木棍。工作台的镐保持 3×3 形状（上行三份头部材料，中下各一木棍）。木棍具有原创像素图标/挤出模型，不以木板占位。缺木棍必须拒绝且无消耗；有限原料成长用例改为自行合成木棍。现有快捷工具配方 UI 与 b1.7.3 工作台门槛仍有差异，后续工位 UI 完整阶段解决，不宣称精确配方 parity。

## S2a 基础建材与冶炼合同

追加稳定体素Cobblestone=17、Glass=18和材料20/21，旧ID不重排，generatorVersion保持4。石头掉落圆石，圆石参与石镐/炉配方并可烧回石头；原有stone-block保存ID继续表示石头。raw-iron保存ID保留，显示为铁矿石并可放回Voxel15，避免旧库存丢失。沙子→玻璃、原木→木炭；冶炼10秒/件，煤和木炭80秒、原木/木板15秒、木棍5秒。有限铁器旅程自行采集圆石并按新时长恢复半程熔炼。

玻璃使用原创cutout纹理与全立方体碰撞，不遮蔽后方不透明面；同类相邻玻璃剔除内部面。TS/Rust/descriptor control三条网格输出保持一致。正常挖玻璃无掉落，放置扣物品且存档保留。新增items必须有正式资源绑定。

验收：确定性冶炼候选验证输入/燃料/产出/半程恢复；正式Authority从圆石/沙/木材经熔炉得到对应物品；网格覆盖玻璃相邻/不透明邻接/未知ID，静态公开入口不变。本阶段仍不覆盖完整方块清单、玻璃物理折射或Beta精确纹理。

玻璃与树叶共享cutout批次时，opacity shader按vertex color alpha中的面材质层采样，不能继续使用统一Leaves层；深度/阴影alpha pass也声明vertex color输入。生产WebGL2编译与真实画面验收；不启用WebGPU。
