# PR 交接默认授权

## 背景与目标

项目需要把已经验收的 change 交给人类审核：使用独立 worktree，按任务成本决定是否并行，并在可合并前持续处理本次相关的 CI 或冲突。本次只将该长期授权和准出定义写入治理文档。

## 范围与非目标

更新 `AGENTS.md`、开发治理和协作路由，明确可将功能分支推送至已配置 `origin`，以目标分支为 base 创建或更新 PR。保留用户的 `local-only` 等单次指令优先级；不自动合并、不绕过分支保护、不扩大权限或其他外部写入授权。没有业务代码、配置或测试语义变更。

## 决策

直接实现：在既有文档中集中说明交接与发布边界，不新增流程文档。可交棒要求最新 HEAD 的必要 CI 通过、无合并冲突且 PR 为 `ready for review`；人类审核仍是待完成状态，单个 `MERGEABLE` 字段不足以代表所有门禁通过。

## 行为

- Given 已验收的 change，When 用户未指定仅本地交付，Then 将功能分支推送至已配置 `origin`，以目标分支为 base 创建或更新精简 PR，随后跟进本 change 相关 CI 与冲突至可交棒。
- Given CI 失败或发生冲突，When 原因与本 change 相关，Then 修复、复验并更新 PR；无变化时不重复通知。
- Given 任务很小或相互依赖，When 并行增加协调成本，Then 可直接完成或按依赖顺序集成，不强制多 agent。

## 验证设计

实现前，文档仍写“默认不 push”，且没有定义 PR 可交棒状态，作为预期 RED。实现后运行格式和仓库链接检查，确认新条款可达且没有旧默认条款。既有 `tests/governance/sdd-testing-governance.test.ts` 也读取治理文档，必须定向执行；首次结果 8/9，因“不自动授权”文案断言失败，保留原有授权边界表达后复验，不改变测试预期。
