# 异步监控的路由补充

## 背景与目标

上一轮主任务反复接收 CI 等待输出并汇报，虽然底层用了确定性脚本，仍消耗主模型轮次。补充监控生命周期，使长等待由脚本、轻量 worker 或低频心跳承担，主任务只处理终态和需要决策的异常。

## 范围与决策

Agile 文档修订：更新现有全局 skill 的版本化源、全局短指针和项目协作规范，再通过现有安装器同步本机。不新增通用调度平台、不修改 runtime/API、游戏代码或验收口径。沿用既有执行器和平台自动化工具。

监控需绑定任务/run id/source SHA、归属、状态来源、截止时间和回报对象。优先平台终态事件或原生 wait/watch；只做状态查询时优先确定性脚本，必要的模型判断交 Terra/high；纯文本机械状态归约才使用可用的 Luna/medium 或 Spark/xhigh。主任务交出监控后应结束当前活动轮次或转做独立工作，不能自己周期唤醒再询问 worker。心跳只读取一次紧凑状态，pending 不汇报；终态、超时或需要人工决定时汇报并停用，避免长期遗留。心跳若不能单独指定模型，不宣称免费或低价模型；以低频和少量唤醒降低成本。CI失败由Terra提取最小失败证据，明确修复再交Sol/high，架构/权限问题回到主任务。

## 行为与测试设计

文档变更无可执行 RED；观察预期：给出“CI剩7分钟”时能派出有期限的只读监控且主任务不忙轮询；给出“CI失败”时返回绑定SHA的失败摘要；HEAD变化、取消和截止时间均有明确终态。不自动重跑、修复、合并或部署。

## 准出与证据

- Static：skill入口按需链接、全局短原则、完整监控契约与项目指针一致；Prettier与skill校验通过。
- Manual supplement：复核上述三个场景及工具能力边界；不把规则当平台拦截器。
- Build/Vitest/Playwright/Midscene：本次仅文档与全局指针，N/A；现有脚本未改，不重复运行已通过的功能套件。PR自动CI由异步监控负责，主任务不等待其逐步输出。

## 任务与交付

主任务负责范围、安装及交付；Terra/high负责有界文档补充和定向检查。估算：0.15–0.3 PD，Terra 10–20分钟、主任务5分钟，24h连续关键路径约25分钟，20%buffer为30分钟；实际credits/API成本及额度占比unknown，不另建goal。

Terra/high 已完成六处文档修订和三个监控场景核对，定向 Prettier 与 skill quick_validate 通过。主任务将通过既有安装器备份后同步全局；本次只补规则，脚本接口未变。推送后绑定最新 SHA 的 CI 由一次有截止期限的低频心跳接管，每次只读取紧凑状态，pending不汇报，终态汇报并停用；不在主任务内等待CI。全局安装收据见 installation.json。长期协作文档已同步更新。
