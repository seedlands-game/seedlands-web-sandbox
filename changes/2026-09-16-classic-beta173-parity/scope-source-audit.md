# b1.7.3 单人主世界、无红石电路范围审计

本审计评估 `inventory.md` 与 `items.md` 的 `做/排/存/核` 口径；v6 的默认裁决已同步到[范围合同](spec.md)，仍待整份合同审核。固定版本身份为 b1.7.3；源码候选固定到 [`740c583`](https://github.com/jacobo-mc/mc_b1.7.3_release/tree/740c583901e1ff1150e9ef37e37dab5bc0e4f807)。重构源码用于定位分支和依赖，不能替代原版运行验收。

## 结论

- 大多数当前 `排` 项的**电路主功能**分类正确；当前 `存` 项也没有发现应直接改为 `做` 的确定性反例。
- 不应把 `Item.redstone`（ID 331）随红石线一起排掉：红石矿无电路也会掉 4–5 粉，而粉是音符盒、时钟和指南针的直接配方输入。现有 `做` 保留正确，但只能是“资源/配方输入”，其右键放置红石线必须排除。
- 铁门方块、铁门物品及 D20 配方三者当前均为 `排`，一致且有直接来源。木门的手动开合不能类推到铁门。
- 三个无电路副作用已在 v6 提议中明确随其电路主功能整体排除：发射器手动容器、红石火把静态照明、动力/探测铁轨被动形态。它们不是“原版不存在”，若用户改选须升版本、预算并补夹具。
- 最大的边界冲突是传送门：黑曜石、打火石和火都保留，但原版火在黑曜石框架中会创建 ID 90。v6 提议明确产品偏离为“框架点火后不生成 portal”，并要求正反例；用户尚未签署整份合同。

## v6 已记录的范围裁决（待整份合同审核）

1. ID 23 发射器及 D54、ID 75/76 红石火把及 D46、ID 27/28 动力/探测轨及 D30/D31 均排除其被动或 UI 形态；普通箱子、火把和铁轨仍保留。它们并非“原版没有这些功能”，是本项目明确偏离。
2. ID 331 红石粉只作音符盒、指南针、时钟和地图链的非电路材料；右键铺线和供电网络排除。ID 46 TNT 的普通点火、ID 25 音符盒的手动触发保留。
3. ID 49 黑曜石框架点火不生成 ID 90；普通火、流体与黑曜石规则继续验收。此边界须在整份合同审核时向用户展示；改选“可见门但禁传送”要升版本与预算。
4. ID 84 唱片机及 ID 2256/2257 保留插入、弹出、事件与独立创作音频的风格体验，不复用原版唱片波形。

上述裁决已进入 [spec.md](spec.md) 与逐项范围登记，但尚未经整份合同审核批准；来源/精确行为缺口仍使本合同保持 `NO-GO`。
