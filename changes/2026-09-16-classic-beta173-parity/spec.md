## 用户要获得的结果、愿景与硬约束

- 用一个可复现的早期 Minecraft 单人玩法对照，验证 Seedlands 的世界、交互、表现和存档能力。**目标是排除项之外当前游玩体验与 Beta 1.7.3 一样**：世界生成、物理、光照、AI/寻路、随机更新、数值、规则、输入反馈与 UI 动线都按该版本逐项对照，不以“有同名方块/实体”充数。
- 对照暂选 **Minecraft Java Beta 1.7.3（2011-07-07）**，固定客户端版本，不把后来的饥饿值、经验、村民、末地等倒灌进来。
- 红石电路、多维度、联机不做；其直接依赖物亦不伪装成可体验功能。普通生存中存在的其余内容按原版行为对照。
- 方块贴图、物品图标、实体、UI、声音和音乐均独立制作；不直接复用原版贴图、音频、字库或代码，不要求像素/波形相同，但用尺寸、轮廓、密度、对比、节奏、反馈和操作动线约束时代风格及体验。“一样”的可执行口径是**行为等价 + 感知体验等效**，不是版权资产字节相等。
- 正常单人 Survival 是验收主路径；原版仅通过调试、命令、修改存档或联机获得的内容列入审计清单但不制造额外可获得性。原版联机专属菜单/系统不实现。

## 本期边界

纳入：主世界地形、生物群系与结构；挖掘/放置/掉落/耐久；合成/熔炼；背包与容器；饥饿值出现前的生命与食物机制；昼夜、天气、照明、火、液体、农作、树木；交通、战斗、被动与敌对生物；主菜单至存档加载的单人体验；像素时代的美术、UI、动画与音频。详细机制与逐项验收见 [mechanics.md](mechanics.md)；其中算法、更新顺序、随机源、碰撞边界和状态持久化都是玩法，不是“引擎内部实现细节”而被免除对照。

排除：红石电路及仅由其驱动的装置链（但保留主世界红石矿、红石粉作为指南针/时钟/地图的材料），下界/末地与传送门及仅由它们获得的材料或生物，所有联机功能。明确列在 [inventory.md](inventory.md) 的不可自然获得内容不增加新玩法。因排除项造成的原版体验差异必须在验收矩阵中可见，不能悄悄改变其他规则。

### 排除依赖的默认裁决（供整份合同审核）

[逐项范围来源审计](scope-source-audit.md)发现同一方块可能同时有红石用途和无电路副作用。本合同按「仍有独立、普通单人且非电路的体验」裁决：音符盒可手动演奏、红石粉可作为其及指南针/时钟的材料、TNT 可点火、唱片机可手动播原创唱片、猪可被主世界闪电转成僵尸猪人，这些保留；粉末右键铺线与所有供电路径不做。发射器的手动容器、红石火把的低亮灯、动力/探测铁轨的被动形态虽在源码中存在，仍随以电路为主功能的装置整体排除；普通箱子、火把和铁轨承担独立的非电路玩法。[38 项排除依赖候选](exclusion-dependency-audit.md)逐项列出被排产物、上游配方、保留输入/玩法正例与普通生存不可进入负例；仍待逐项来源和夹具审核。原版注册但本合同排除的方块、物品与配方只审计 ID、依赖和自然生存不可进入负例，不实施其 UI/模型/机制。这是明确的范围偏离，不冒称原版没有这些行为。

另一个明确偏离是传送门。固定源码的 [BlockFire](https://github.com/jacobo-mc/mc_b1.7.3_release/blob/740c583901e1ff1150e9ef37e37dab5bc0e4f807/1.7.3-LTS/src/minecraft/net/minecraft/src/BlockFire.java#L191-L197) 会在黑曜石框架点火时调用 [BlockPortal.tryToCreatePortal](https://github.com/jacobo-mc/mc_b1.7.3_release/blob/740c583901e1ff1150e9ef37e37dab5bc0e4f807/1.7.3-LTS/src/minecraft/net/minecraft/src/BlockPortal.java#L37-L81)。既然用户排除多维度及传送门，本合同选择**框架点火不生成 ID 90**，但黑曜石、水熔岩反应及普通点火/火传播仍按其自身规则保留。验收必须同一夹具给「普通可燃目标可点燃」正例与「完整黑曜石框架点火后仍无 ID 90/维度入口」负例。此偏离应在用户开工审核时显式展示；若用户选择保留可见传送门但禁用传送，需要提升合同版本、预算及画面/存档验收，不可静默替换。

## 实现分层硬边界

本期以 **Kernel 零改动** 作为引擎能力验证的前提，而非鼓励把玩法硬塞到 Kernel。所有实施工作单元按 [改动台账](boundary-ledger.md)逐项归类、留证，并在阶段结束按实际 diff 回填：

- **ERROR-kernel**：凡需修改 `packages/kernel` 的生产代码、公开合同、测试或配置，或虽不改该目录却实质改变 Kernel 承诺的身份、授权、事务、调度和存档不变量，立即停止该实现路径。先出具“先前缺陷—本次需求—备选与拟改方案—理由—影响/兼容—RED/验收”的证据报告，单独取得用户审批后才能执行。仅发现疑似缺口不是已经证明 Kernel 有缺陷；若现有公开 API 可以满足，必须回到 stdlib/Playbook 实现。
- **WARNING-stdlib**：预期有部分标准库机制扩展；每处修改都记录现有能力缺口、Classic 消费场景、公开接口/状态 owner、测试与实际 diff，解释为何不能仅由 Playbook 定义和组装完成。记录是对此前基础库能力不完备的可追溯反馈，**不新增一道人为审批**；原有 Breaking/SDD 门禁仍适用。
- **NORMAL-playbook**：方块、实体、物品、配方、掉落、规则参数、模块选择与组装优先在 `playbooks/classic`，逐项登记和验收，属于预期改动。不得借 Playbook 直接写 Kernel/stdlib 私有状态或建立第二套权威。

`apps/web` 的输入、UI、渲染、动画、音频和浏览器存档适配，以及测试、原创资源与构建配置，单独记为**客户端/工程侧改动**，不误归为 `NORMAL-playbook`，也不能用客户端补丁规避应由 Kernel/stdlib 保证的权威行为。一个功能跨层时按**实际修改点分别记多行**，最高风险项不得被正常项抵消。此边界是当前用户明确约束，优先于任何笼统“完成玩法”授权。

## 研究和冻结门槛

**开工门槛只针对完整 Classic 范围审核一次。** 可以分批查资料和编写 case，但不得以 `P0/P1`、第一天生存或任何竖切面先行冻结合同、先行批准玩法实施；已完成的小切面只算全量清单中的既有证据，不代表剩余内容已被验收。全部纳入项及其元数据/变体、全部玩法机制、原创音画与 UI 的验收口径、排除项依赖和分层边界都关闭后，才向用户提交完整合同版本/hash 审核并申请开工。资料无法证明的项目保持阻断，不改称下一阶段或默认略过。

1. Mojang 官方版本清单与客户端 SHA-1 固定为 `b1.7.3` / `43db9b498cb67058d2e12d394e6507722e71bb45`。登记依据：[官方版本元数据](https://piston-meta.mojang.com/v1/packages/44f6969326bd45aa00dcd3c4ca3a7c05ebb24c04/b1.7.3.json)。**不在本地运行、安装或分发原版客户端/服务端，也不把它作为 Harness oracle**；只交付可审计清单、来源等级与预注册验收标准。
2. 本清单的方块 ID、实体注册名、配方直列输出曾依据该版本客户端做静态核对；静态注册不证明游戏行为。配方输入排列、数量、批量配方和世界状态交互若无可追溯资料，标 `REFERENCE_GAP`，不让 Seedlands 自己的输出定义“原版真值”。出现冲突时修订 inventory、reference case 与估算，版本提升后重新审核。
3. 每一机制先给出有来源的期望行为、正反例与可执行 RED，或记录不能自动化的视觉/音频观察；资料不足时保留未验证结论，不伪造数值。世界生成、权威状态、存档版本与渲染/性能的 Breaking 合同需按[开发治理](../../docs/development-governance.md)另行审核。本草案不替代这些审批。
4. 当前 CI 冻结只覆盖 Kernel/stdlib 确定性测试和静态边界；Classic、浏览器与视觉体验**尚无产品验收**。恢复时须修订[CI 测试边界](../../docs/ci-testing.md)，以浏览器、视觉、音频和人工旁观证据分别验收。
5. 当前 `playbooks/classic/src/blocks.ts` 的数字 9 是 Seedlands 荧石块，而 Beta 1.7.3 的 ID 9 是静止水；当前 ID 0–15 不是 Mojang 调色板，不能直接重用旧数字而让旧存档静默变质。对照内容须用显式版本映射、新世界 generatorVersion 和旧档迁移/拒绝验证。
6. 每个阶段在开始前登记预计 owner，结束时按实际改动文件和公开合同回填分类。任何 `ERROR-kernel` 未获单独批准都保持 BLOCKED；不得以 stdlib/Web 转发、直接读写内部状态或放宽测试掩盖它。

## 验收目标

- 启动、创建世界、前 30 分钟生存、采矿/合成/熔炼/建造、夜间战斗、耕作、钓鱼、运输、死亡重生、保存/加载均有版本化对照脚本和回放证据。
- 对每个纳入的 inventory 行，至少有来源 ID、可获得性、行为/视觉预期、测试类型与完成状态；排除行可解释依赖原因。
- 对同一输入序列、种子和初态，在[固定 Harness](harness-acceptance.md)里比较 Seedlands 的可见世界、物理轨迹、每 tick 状态变迁、光照、液体、火、AI 决策与生成位置，验证重放/存档恢复确定性。与 b1.7.3 的具体数值/算法一致性只根据预注册、有来源的 reference case 宣称；没有来源则 `REFERENCE_GAP`，不能把“看起来像”或自我一致冒充原版 1:1。
- 独立资产的风格盲测和交互并排评审通过，但不使用原版资产参与产品构建或分发。
- 每个实施阶段的改动台账与实际 diff 一致；Kernel 无未审批改动，stdlib 警告项有缺口说明与验收，Playbook 正常项可追到对应内容或机制；客户端/工程侧单列，不冒充引擎层零改动证明。

## 未决，实施前必须锁定

- Beta 1.7.3 的各方块元数据、掉落概率、配方镜像/数量/形状、群系与结构生成参数的逐条**完整来源化 reference case**；当前 [reference-cases.json](reference-cases.json) 已登记有来源的局部事实与 `REFERENCE_GAP`，不能把局部事实当整项通过。不得以“待本地运行原版”作为前置条件。
- 对红石依赖边缘项按“无电路仍可自然使用”规则继续审计。音符盒手动触发和雷击猪转僵尸猪人已有静态来源并纳入；铁门仍排除，唱片机/TNT 非红石路径保留。不得要求在本地运行原版来关闭其余缺口。
- 性能与画质目标硬件、分辨率、视距、帧率，以及美术/音频独立创作供应方式和成本；未给定时只估人日和模型用量，不宣称含采购报价。
