# Classic b1.7.3 固定 Harness 环境与验收合同 v16 草案（未冻结）

**交付性质：规范，不是已存在的可运行 Harness，也不是任何玩法已通过。** 本期不运行、不安装、不分发 Minecraft Beta 1.7.3 客户端或服务端；不以原版程序作为 CI oracle。目标是把后续 Seedlands 实现放进同一个版本化上下文，按事先冻结的清单和标准验收。当前 `main` 仅运行静态检查与 Kernel/stdlib 确定性测试；`harness:classic`、生产浏览器 job 与性能门禁在本 checkout **不存在**。未来恢复时遵守 [CI 测试边界](../../docs/ci-testing.md) 和 [Harness 合同](../../docs/harness-contracts.md)，本文件不能冒充恢复完成。

## 1. 对照依据与结论等级

对照版本身份固定为 Mojang [b1.7.3 官方元数据](https://piston-meta.mojang.com/v1/packages/44f6969326bd45aa00dcd3c4ca3a7c05ebb24c04/b1.7.3.json)（客户端 SHA-1 `43db9b498cb67058d2e12d394e6507722e71bb45`）；此身份只说明选择了哪个版本，不自动给出物理、AI 或 UI 细节。用户明确排除红石电路、多维度、联机；独立创作所有贴图、模型、UI 字体、音效和音乐，按风格/体验等效而非资产字节相等验收。

每个预期值必须写入版本化 reference case：`caseId / b173Feature / expected / evidenceUri或可审计推导 / evidenceLevel / confidence / exception / ownerReview`。证据优先级：①该版本官方元数据、原始版本说明或可合法静态核对的版本注册信息；②可定位时间和版本的同期公开操作记录；③两个互相独立的社区资料；④团队推断。②③可作为候选，④不能作为“原版事实”封板；冲突或查无依据标 `REFERENCE_GAP`。本次 [522 条父项](reference-cases.json)、[618 条有限变体与 8 个开放状态族](variant-cases.json) 已含 ID/动作、部分预期、来源链接、证据待审字段与夹具占位；当前的 `review.evidenceLevel` 是**候选来源类别**，不是已经通过上述优先级裁决，`confidence=UNREVIEWED`、`ownerReview=PENDING`、`fixture.status=NOT_FIXED`。其中 19 项为 `PROJECT_CONTRACT_CANDIDATE_REVIEW`，已补本项目 Harness/原创体验/性能条款候选，而非 Minecraft 原版真值。各项详细缺口见 `unresolved` 与[候选审核队列](reference-worklist.md)。有来源的 **部分预期不等于整项已证实**。不得由待测 Seedlands 实现生成 expected 后又以 expected 证明它对齐原版，也不得把后续 Minecraft 版本行为倒灌进来。

测试结论分开陈述：

- `REFERENCE_READY`：**开工前**的整份合同已获审核：每个纳入项及变体有明确、可定位且已裁决来源的 expected、固定夹具设计、正反例和验收层；排除项有可追溯的依赖理由及「不得从普通生存进入」负例；项目治理项用本项目合同而非伪造原版 oracle。它不要求 Classic 代码、RED 脚本、原创资产或运行回执已经存在，也不表示产品通过。不能只对一个切面赋予此状态。
- `CONTRACT_PASS`：实现满足本文件已冻结、有来源的 expected 和完整 Harness 证据；只说明规定上下文内通过。
- `REFERENCE_GAP`：原版具体数值/行为尚无足够依据，或清单项尚无 expected；即使 Seedlands 内部测试绿，也**不能宣称该项 1:1**。
- `EXPERIENCE_ACCEPTED`：用户或其指定评审者对独立资产、UI、音画节奏与手感签署体验等效；自动测试不能代签。
- **完整 b1.7.3 对照准出**需要所有纳入项同时达到 `CONTRACT_PASS`、无 `REFERENCE_GAP`，且体验项 `EXPERIENCE_ACCEPTED`；若受无法运行原版的限制无法关闭个别证据，最终报告只能列明确差异/未验证项，不能宣称“完全一样”。

三个时点不可混用：本 change 只争取**整份合同 `REFERENCE_READY` 后请用户确认开工**；随后独立实施 change 才取得可执行 RED/GREEN、生产 Browser Harness 回执和最终 `CONTRACT_PASS`。本期没有运行原版的计划，来源裁决可通过固定版本元数据、可合法静态核对的同版本代码/字节码及独立同期旁证完成；单个重构仓库的文件存在性只够标「候选」。若资料不足，保留具体 `REFERENCE_GAP` 并给整份合同 `NO-GO`，不得把缺口留给 Seedlands 实现来反推。

范围判定先于用例深度：`做` 要覆盖所有可体验的行为与变体；`存` 只覆盖会影响纳入玩法的内部状态、可达性和存档，不凭注册身份创造自然获取途径；`排` 只须锁定排除依据、与纳入内容的依赖边及普通生存不可进入的负例，**不要求实现被排除功能**。`M01/M34–M36` 等来源/证据/性能/分层治理项使用本项目可执行标准，不要求编造 Minecraft 原版 expected。凡边缘项仍标 `核`，不能计入已关闭范围。

## 3. 版本化场景上下文

固定 [机器可读 profile](harness-profile.json) 中的 `profileId=classic-b173-singleplayer-v16`，`scenarioVersion=16`，`referenceCaseSetVersion=16`，主路径 `Survival / Normal`、默认 seed `classic-b173-acceptance-v1`、生成版本标识 `classic-b173-overworld-v1`、视距 8 chunks、时间 tick 0、晴天、空背包，无联机、红石电路或其他维度入口。上述值是 **Harness 测试上下文**，不声称它们全是原版菜单默认值。所有 case 的 `initialInventory`、`difficulty`、`worldTimeTick`、`weather`、`seed`、`generatorVersion`、`loadedChunks`、`fixtureDigest` 与输入 trace 必须在运行前确定并写入 receipt。变更这些值要提高版本、审阅差异，旧证据不能自动继承。

`P0–P5` 是**本 change 的拟定场景编号**，不是旧 Harness 文档的 C0–C5，也不表示当前 checkout 已有这些测试。`P1` 与 `P2` 检验产品路径；每一具体方块、实体和配方仍靠参数化合同矩阵覆盖，不能指望一条浏览器旅程碰巧触及所有条目。真实游玩旅程不能用 `__seedlandsHarness.movePlayerTo / setVoxelAt / advanceGameplay / executeGameplayCommand` 达成目标；它们只可用于明确标识的前置夹具与只读诊断边界。

P5 不可用普通 `browser.newContext()` 假装浏览器重启：Playwright [说明该 API 创建隔离的 incognito context](https://playwright.dev/docs/api/class-browser#browser-new-context)，不会共享前一个 context 的存储。使用 `launchPersistentContext(userDataDir)` 时每个 run 必须创建**专用空目录**，只在该 run 内重开相同目录及**同一 origin（含端口）**；不能指向用户日常浏览器 profile，也不能让两个浏览器进程同时占用它。实现前仍须在固定 CI 环境实测 IndexedDB 存档关闭/重开读回，文档修正本身不算 P5 通过。

### 数值与概率的停止线

- 原版明确数值可考证时，先把期望常量、来源与范围写入 reference case；测试 **exact**，不能运行后调整容差。物理浮点有跨宿主差异时，只对可观测位移/角度设置事先批准的数值容差，且在 same-host 重放必须确定；不能以“接近”掩盖事件次序差异。
- 对世界生成、刷怪、掉落概率、随机生长和音频/视觉分布，固定 seed 与 RNG 调用序列做确定性例，另在预注册 seed 集合做分布例。样本量、统计量、置信/容差须由该机制的参考依据与预实验给出并随 case 版本冻结；资料缺失则 `REFERENCE_GAP`，不临时编造 1:1 百分比。
- 原创美术采用产品截图/视频并排的人审量表：体素像素密度、色板/对比、低多边形轮廓、动画帧节奏、UI 排版/操作动线、天气/昼夜氛围各项“等效/不等效+证据”；音频同理覆盖材质打击声、实体反馈、环境/天气、UI、音乐/静默比例。评审者由用户指定；原版资产不导入产品包。
- 性能、内存、帧率和输入延迟的硬阈值目前 **NOT_SET**：未指定参考设备/驱动及 A/A 噪声，不能从旧基线或 CI 超时推导。它不妨碍继续编写单项行为候选，却阻断本次**全范围开工合同**的 `REFERENCE_READY`；未来产品准出还须独立性能 profile、预算与实测。

## 5. 运行结果与门禁

每次结果必须有 `runId / profileVersion / caseIds / sourceSha / lockDigest / Pack与资源摘要 / browser与后端身份 / storageProfileDigest与origin / seed与fixtureDigest / inputTraceDigest / expectedVersion / 实际 owner 状态与事件 / 产物摘要 / 起止时间 / 未运行理由`。P5 另记录关闭、重新启动、持久化事务完成与读回时刻；不同 run 不复用 profile。保存失败和未执行阶段，不用最后一次重试覆盖。HTTP 200、启动日志、输入 ack、计数增长、单张截图和 Runner 自报 `PASS` 均不是完成证据；浏览器需关联同 trace 的 Worker 完成、权威提交和 postrender 消费。

运行结果枚举：`PASS`、`FAIL`、`BLOCKED`、`NOT_RUN`、`REFERENCE_GAP`、`NOT_APPLICABLE`，只用于未来单案执行；开工前合同决策仅为 `REFERENCE_READY` 或 `NO_GO`。两层不能互写。完整准出要求：

1. 环境/源码/产物/场景/期望身份全部匹配；不匹配立即 `BLOCKED`，不能退化成另一浏览器/后端偷偷继续。
2. 所有纳入内容行和机制子项覆盖率 **100%**，选中的测试真实执行且全部 `PASS`；`todo`、`skip`、flaky、重试通过、未执行均不能算通过。
3. 用户排除项不出现在自然生存路径；红石粉作为非电路材料的例外按清单显式测试；旧存档不静默重解释 ID。
4. 产品旅程 `P0–P5` 全过且关键反例会失败；UI/视觉/音频的人审通过；未关 `REFERENCE_GAP` 或性能 `NOT_SET` 时不能宣称完整 1:1 游玩体验。
5. 遵守 [分层门禁](boundary-ledger.md)：Kernel 未授权 diff 为 `ERROR` 并停止，stdlib 变更有 WARNING 记录，Playbook/Web 改动按 owner 归档。各证据层结论分别报告，不把静态/Headless/Browser/人工互相代替。
