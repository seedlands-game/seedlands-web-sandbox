# 本轮性能优化采纳方案

最终正式采纳TS数据平面修复及General Worker的Rust W02–W06，W06启用标准SIMD；Fluid默认保持TS。第二轮10组/30次确认已通过，首轮W02–W07的回归数据完整保留。A 为冻结提交79e05c5、Wasm关闭；A′仅TS数据平面修复；B在A′上启用Rust集合。控制平面继续AoS，数据平面使用紧凑数值数组和明确所有权，不重写权威状态机。

## 已采纳的 Rust 内核

10个平衡配对block，每变体预热至少1秒并覆盖30个corpus，120个测量任务。单位ms；计算含适配准备/输出，任务再包含输入clone、既有Worker往返。区间以配对block重采样，不把数千任务当独立样本。

W06 SIMD相对同算法/布局Rust标量：计算0.2336→0.1881ms（19.48%，95%区间17.38–21.57%）；任务0.6251→0.5835ms（6.65%，5.08–8.32%）。只使用标准simd128，关闭relaxed SIMD与自动vectorize，保留scalar能力回退。

## 已采纳的 TS 修复

无返回实体写回、导航窗口校验与open集合选取、已移交缓冲消费、融合Mesh打包、索引循环occupancy、TS列预采样。编解码密集查表/有界输出/索引CRC已实现并通过等价测试。正式重测W14计算1.1231→0.7307ms（34.94%），任务1.1868→0.7888ms（33.53%，95%区间32.02–35.80%）；W15计算0.0892→0.0462ms（48.13%），任务0.1078→0.0725ms（32.77%，19.97–40.14%）。

正式生产压缩Worker的TS数据：129实体写回0.05117→0.037015ms/批（27.66%）；513实体0.19918→0.144985ms/批（27.21%）；导航完整查询0.40788→0.09937ms（75.64%）；collision baseline接收0.00684→0.000755ms（88.96%）；generated prepared-hit含CRC验证1.05173→1.04311ms（0.82%）。尾分位数是批均值分布，不能称单次请求p95。

窗口验证1386格原0.08926ms，修复后的100次批平均低于0.001ms/次；32768格原2.5787ms，修复的10次批平均低于0.01ms/次。原记录中的0和100%不表示零成本。显式copy/allocation账详见[分配账本](evidence/allocation-ledger.md)。

## 未默认采纳的项目

- W07：128 frontier分项任务4.6982→2.9555ms（37.09%，30.67–45.64%），但首轮组合相对优化TS的编辑p99慢15.71%。收缩后未再观察到明确回归；默认TS，Rust仅显式实验。两批不是随机交错的W07单因素对照，不能据此证明唯一根因。
- W10：首轮Uint8Array.from控制与实际生产不符，禁止用于采纳。修正后32K连续输入TS→Rust SIMD计算0.0339→0.0065ms，任务0.0692→0.0397ms（42.65%，36.02–50.52%），但仅省0.0295ms；真实Authority路径还需体素聚集和新增Wasm消费者，当前没有对应连续大批接口。1项输入SIMD任务反而慢4.21%且区间跨零；1024项核内差距不足0.001ms，不能可靠解释单次计时。采纳生产isSolid循环消除临时数组，保留SIMD原型，不增加Authority实例。
- W14：优化TS→Rust任务0.7888→0.7654ms，仅省0.0234ms（2.97%，区间−2.82–6.68%）；p95从1.1505升至1.3310ms（慢15.69%，区间10.13–23.92%）。不采纳Rust生产接口，避免低频持久化路径新增实例、复制和维护成本；纯Rust codec保留等价测试。
- W15：优化TS→Rust计算0.0462→0.0583ms（慢26.13%，区间19.96–31.81%），任务0.0725→0.0781ms且区间跨零。不采纳Rust/MoonBit CRC生产接口，采用索引TS循环。
- MoonBit：所有已有实现参与相同corpus公平对照，本轮W02–W07未超过Rust的任务表现。保留研究产物，不增加浏览器专用生产双实现；较小体积不足以抵消额外等价性/确定性维护。
- W01/W16：保留历史采样和不迁结论，完整宏观数学/缓存严格对等需5–7工程日，地图还依赖它；历史CPU采样详见[既有候选筛选](../2026-09-06-moonbit-wasm-workload-experiment/remaining-candidate-decision.md)，不是本轮A/B。
- W08/W09/W11：本轮优先修复实体写回与导航分配；完整物理/导航移植、packed PhysicsFrame、Logic直连未实施。保留同步提交、locale优先级、unknown/revision约束；未测迁移收益不写成零。
- W12/W13/W17–W30：沿用[全量责任清单](../2026-09-06-moonbit-wasm-workload-experiment/workloads.md)分类。低成本查询、权威编排、消息、持久化I/O、UI、渲染和GPU宿主职责保持TS/PlayCanvas。不为潜在未来内核改写完整状态或管线。

## 运行、维护与准出

维持五个Web Worker：General使用w02–w06，Fluid/Authority/Logic/Persistence仍TS，W07仅保留显式实验选择。每个启用角色独立Wasm实例，无共享内存、无Wasm内线程、无新增COOP/COEP要求。保留WebGL2，不引入GPU compute/WebGPU。Rust core不依赖浏览器/Node，Wasm适配独立；本轮不实现Node Dedicated Server、Node-API或完整Rust server。

收缩后仅General一个18MiB线性内存实例；首轮W02–W07为两个实例共36MiB容量。这些均不等于RSS。微基准同时加载研究模块，不能把其初始化总量当每后端启动成本。统一实验记录实际实例化hash、静态产物字节（扫描清单不是实际下载量）、端口与源码绑定、CPU非idle采样、帧/physics/启动/编辑可见反馈、结束时heap；RSS/GC与跨并发扩展效率为NOT_COLLECTED。

统一正式运行前冻结本方案及构建，10个同seed配对block，对每个block比较权威轨迹和任务量。只认正式隔离采样；失败/预检保留。若B出现明确用户体验回归则消融或撤回；不把核内倍率相加，不把headless约60Hz帧节奏称实体设备FPS验收。

## 首轮组合止损与确认规则

首轮原方案hash为 `295a4cf84326bf74a18bbc310e8bd0fbc6a74fcb1a2c00338ad962159a6e0684`。10组完整数据中A′→B编辑p99慢15.71% [0.44,32.99]，触发消融；W07从默认启用改为显式实验选择。分段只定位到提交前阶段，不把相关性写成W07确定根因。第二批仍用完整10组空白A/修复TS A′/General Rust B确认；若仍有明确回归，最终默认TS修复。详见[首轮完整数据](first-combination-results.md)。

## 最终准出与成本

第二批 `combined-final-2`：30run有效、10组轨迹/工作量门禁通过，额外逐role核验通过。相对空白A，进入可玩5.2320→1.0729秒（79.49% [78.48,80.33]），30秒非idle CPU采样9.5903→7.3478秒（23.38% [19.49,26.84]），编辑p95 70.5660→54.8035ms（22.34% [11.55,31.45]），p99 72.0252→57.4407ms（20.25% [8.83,30.62]）。帧节奏与physics cost未显示有意义的改善。

相对优化TS A′，Rust额外缩短进入可玩35.78ms（3.23% [2.83,3.75]）；General非idle样本均值253.10→202.09ms，但全角色CPU平均反而多2.42%，区间跨零，不能宣称额外省整体CPU。编辑p95/p99的增量改善区间也跨零。采纳依据是独立高负载任务净收益、启动增量、纯core复用和第二批没有明确用户尾延迟回归，绝不是把所有收益归Rust。该样本量也不能证明所有设备/负载绝无回归。

成本为一个18MiB线性内存容量、Rust固定工具链、标量/SIMD两产物及等价/回退门禁；RSS/GC未采集。生产完整保留TS回退及 `?wasm=off`，不扩大Authority/Logic/Persistence的Wasm实例，不新增Node消费者。UI/渲染规则未变，无额外GPU路径。完整表见[最终结果](results.md)。
