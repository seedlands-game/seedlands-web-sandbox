# 协同计算上移的性能不退化合同

2026-09-07 用户要求：网络迁移会将原集成架构中由客户端协同执行的服务端计算全部上移到权威服务端，必须重点观测，退化则解决。本附件补充[实验合同](experiments.md)与[网络选型](network-selection.md)，属于 A13 准出门禁；不是采集到坏结果也可以仅写“常驻有价值”的观察项。当前没有实测数据。

## 一、迁移清单与完整成本

当前 `src/app/browser-worker-session.ts` 中的 `generateAuthorityChunk` 经浏览器 compute 生成并回送 `acceptWorkerCanonical`；`onBootstrapGeneration` 通过 compute 找出生点；Fluid observation/candidate 与 Logic observation/intents 也经浏览器转发。Dedicated 路径全部改由可信服务端编排、执行、校验和提交，不能依赖客户端在线或回送权威候选来补性能。

| 上移职责                   | 原集成路径                                           | Dedicated 路径                                        | 必测结果                                                        |
| -------------------------- | ---------------------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------- |
| canonical 生成与安全出生点 | 浏览器 compute、主线程回送 Authority                 | 服务端生成需求与 TS executor，候选回到 Authority 校验 | 首可玩、请求到 canonical 就绪、有效 Chunk/s、生成排队与重复工作 |
| Fluid                      | Authority → 浏览器调度/Fluid Worker → candidate 回送 | 服务端观察、调度、计算、校验与提交                    | observation age、有效提交/s、失效/重算率、提交到客户端可见时间  |
| Logic/NPC                  | Authority → 浏览器 Logic client/Worker → intents     | 服务端有界观察和 Logic lane → 权威 Action             | 决策/动作 p95、饥饿、完成动作/s、观察新鲜度与实体进展           |
| 世界需求/碰撞镜像同步      | 同机 Worker/主线程消息与派生数据                     | 服务端裁定订阅，传版本化世界数据，客户端建镜像        | 输入路径碰撞等待、Chunk 完整可用时间、resync、校正误差          |
| 保存与恢复                 | Authority 保存合同 + 浏览器持久化 lane               | 同一冻结语义 + Node 文件执行器                        | checkpoint/durable 延迟、保存时 tick/streaming 干扰             |

客户端保留预测、渲染/mesh、GPU、表现与派生碰撞镜像；“协同计算全部上移”不表示把这些玩家表现也搬到服务端。任何审计中新发现的权威计算回送路径都补入清单，不能只迁表中已知回调后假定完成。远端模式禁止启动承担 canonical/Fluid/Logic 权威候选的客户端 lane，静态检查、资源清单和断开客户端后世界继续推进共同验证。

同一 work id 关联 `demand → enqueue → start/end → candidate → validate/commit → project/encode → transport → decode/apply → collision/mesh-ready → displayed`。记录各端单调时钟、跨进程关联及同步误差；不能直接相减两台机器未校准的时间。端到端输入由同客户端时钟测发送/收到确认/显示，服务器各段独立计时，网络只报告可辨识的残差或实测 RTT，不能用 p95 减 p95 伪造精确分解。

每阶段按相同工作量记 CPU/heap/RSS/GC、队列长度和最老年龄、在途/发送字节、tick debt/deadline miss、拒绝/取消/重算/饥饿、吞吐与世界进展。线程池“任务完成更多”若有效提交没增加或做了重复工作，不算收益；减频、降视距/实体/流体预算、跳过保存或碰撞校验都不能作为过关方式。

## 二、专门的职责上移对照

保留 B0/B1/N-eq，不把职责变化混进 L1 的纯宿主结论。在相同客户端/服务器硬件与资源预算上增加迁移检查点：

1. B0 原集成产品 → B1 接口/职责整理后的集成产品：确认原本地世界没有回归。
2. B1-server trace → N-eq 无外部网络：canonical/Fluid/Logic 全量工作由 Node 承担，固定语料、完成量、频率、池角色与内存 store，单独定位上移与宿主调度。
3. N-eq 受控无网络 → 同机 reference codec/transport → 选定网络：观察两端 CPU 竞争、协议排队、镜像/渲染就绪与玩家可见路径，不给各组偷偷分配更多 CPU。
4. 同一 Node 服务器的 loopback/LAN/隔离 WAN 条件分组；CT105 是真实共享宿主验证，不拿其 CPU 与开发机直接比“runtime 提升”。原来 browser 的 general lane 含 mesh，明确拆出服务计算和表现成本，不能从总账中抹去。

每次只改变一类因素；诊断某个 lane 时仍验证混合负载，不能只优化离线 Fluid 而让实时输入饥饿。服务器进程 CPU/RSS 上升本身并不等于退化，因为工作从客户端转移：比较相同有效工作下两端总成本、服务端分阶段成本和实际资源预算，并报告成本转移，不能只展示客户端下降。

## 三、准出判定

**目标是不退化，原 F1–F4 的“允许其他项最多 5% 退化”不能用来豁免 A13。** 在固定场景与设备上预登记核心指标，再做 A/A、独立配对、置信区间和 holdout。目标指标包括 frame p95/p99、首可玩、Chunk 可用/碰撞等待、预测反馈、NPC/Fluid 有效进展、tick/debt、持久化延迟、队列年龄与两端成本。

- 本地 B1 对 B0、同资源无网络上移组和 loopback 产品组：核心延迟/成本的目标相对变化 ≤0，有效吞吐/世界进展 ≥0；必须报告原始值和统计不确定性。已确认退化即失败，不能用另一个指标更好抵消。
- 若区间跨越零，只能写不确定，不能以“没有显著发现退化”宣称已证明不退化。按预登记预算改善测量/定位；仍不确定则该门禁未完成。微小差异是否处于测量分辨率内由运行前 A/A 定义，不事后提高容差；任何拟议可接受退化都需用户改变此合同。
- WAN 必然增加传输时间，不能承诺远端权威确认与同机内存消息一样快。用户侧预测响应、碰撞一致、世界进展与服务端计算仍受不退化门禁保护；网络确认另外使用预登记的可玩 SLO，不能把所有额外延迟都解释为物理 RTT。
- 拟议 WAN SLO：在 RTT≤150 ms、丢包≤1% 的受控目标档，输入确认 p95 ≤该 run 实测 RTT p95 + 两个 physics tick 周期 +20 ms；最新可用 pose 年龄 p95 ≤RTT p95 + 两个网络更新周期 +20 ms。它们是待审核的总时延预算，不是 p95 可加性的统计推导，20 ms 也不是可以让本地计算退化的额度。更差网络档仍测正确性、降级/恢复和实际数据，不假称全部档位体验等同 LAN。正式冻结前若改变目标档/SLO，更新 hash。
- 服务器计算窗口过载、有效 NPC/Fluid 进展下降、客户端新增碰撞停顿、可观测穿透/重复动作、无限积压/内存增长，直接不准出。已批准预算内持续修复；超预算时保存未完成状态并重估，不能改称“可玩即可”。

受控长样本的性能门禁由当前 change 报告执行，CI 不新增跨机器固定 FPS 阈值。正确性/时间预算可以在受控环境确定性验证，但真实性能必须有实际采样；Manual supplement 不能替代所需的程序化证据。

## 四、退化处理闭环

发现退化 → 按同一 trace 定位计算/排队/数据投影/网络/镜像/mesh 阶段 → 提出最小修复 → RED/可复现坏样本 → 修复 → 同条件配对复验 → W-mixed/holdout 验收。记录问题、影响幅度、修复成本与剩余预算，不仅留下“负收益”的实验结论。

优先修复重复计算/传输和错误调度，使用既有取消/合并与有界优先级、预算隔离和批处理；必要时比较池规模、codec、多流和复制成本。若 F1/F2 等选项用于解决迁移退化，单列“修复所需配置”对全关和最终组合的结果，不把未修复基线当作唯一对手夸大优化收益。可关闭无益优化，但完整计算上移及核心不退化仍必须满足。
