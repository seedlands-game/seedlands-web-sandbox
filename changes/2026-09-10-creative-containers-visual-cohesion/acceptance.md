## 行为证据

- 创造交互：先证实默认右键无法打开已正式放置的创造工位，再修复目标使用优先级、Shift 绕过使用的放置行为、真实工位 UI 与模式切换的光标归还。核心及输入/UI 定向 5 文件23项通过；实际 Browser 使用真实鼠标/键盘，不以直接写库存替代行为。
- 资产密度：初始测试证实工具源仍是16×16。新工具/成长资源为32×32，模型显式32 pixelsPerUnit，旧模型省略该字段时仍按16解释；复制、导出/导入保留密度及网格尺寸。
- 缩略图：原先出现不透明黑底、过大留白和混用直接像素图。现在第一方默认图全部由实际模型渲染512×512透明PNG，正交取景，实测轮廓最长边接受83%–94%。最终槽位图像盒同时接受轮廓相对槽高至少65%的检查，避免只把PNG变大而界面仍小。
- 居中：真实页面先测得煤图标向右4.0625px、向下8px（RED）。原因是全局按钮padding覆盖槽位内边距，而快捷栏上下留白也不对称。图像独立居中后，桌面背包/快捷栏轮廓中心偏差为0，720px窄屏快捷栏最大约0.008 CSS px；数量、快捷键和耐久独立叠加。工作台材料/结果也通过轮廓中心检查。原始测量见[icon-centers.json](evidence/icon-centers.json)，阈值两轴均≤1 CSS px。
- 手持：普通物品缩放保持0.55，工具为0.95。竖屏单独调整缩放、方向与手部锚点，世界尺寸和权威攻击未改变。1280×720、720×960、1920×810中逐一查看五种工具待机，以及木剑蓄力、命中、收招原始帧；工具头/剑尖未被侧边或顶部裁切。阶段由正式攻击输入和公开时钟推进，并断言对应战斗状态。
- 兼容性：[独立审阅](review.md)发现旧工位像素ID被移除和空模型取景问题。恢复旧工作台/箱子/炉体稳定ID及原像素数据；旧项目的仅引用依赖、像素覆盖、新图像覆盖优先级共5项检查通过。空网格在投影前明确失败，不向场景写入NaN。后续追加8种工具/资源的旧纹理覆盖兼容：保留所有原16px纹理，新默认模型引用独立`:detail`源；仅旧纹理覆盖选原16px模型，显式模型或detail覆盖优先。16个旧覆盖/自定义引用案例从RED到GREEN，另以基线payload hash固定11个原纹理，并验证覆盖优先级。同时修复内置目录增长挤占旧项目容量的问题：项目和外部原生包仍最多128项用户资产，内部合并额外计入可信内置目录的预算；64/71原生资产及105/115非原生资产旧项目、128项合法边界和129项拒绝均有回归检查。不修改旧存档身份或批量重写数据。

## 几何合同的确定性对照

32像素图按旧逐像素正反面生成方式使部分工具超过既有1000三角形预算。本轮将正反面同色横向连续像素合成面，保留逐像素轮廓侧面与内部面剔除，未放宽三角形上限。

[mesh-surface-ab.json](evidence/mesh-surface-ab.json) 使用相同32px资产和像素密度，对比旧算法与合并算法。逐法线、逐颜色累计三角面面积相等；木剑828→640、木斧1200→756、石镐1340→872、木/铁镐1340→856，其余材料也在预算内。这是几何表面与容量合同证据，没有计时实验，也不宣称帧率或运行时性能提升。
