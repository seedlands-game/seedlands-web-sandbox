# 创造容器交互与物品视觉一致性修复

## 状态与授权

Active / Agile。基线 `23e93e2`。用户明确要求：修复创造模式右键容器不可用；修复工具、剑、新方块贴图模糊与风格不统一；全部解决后 push，创建 Sol worker 持续跟进 CI 到可合入。后续要求先释放当前会话所有 dev server，已停止 4173/4174 并确认释放；验证服务按需临时运行，结束即关闭。

本 change 修复现有玩法体验，不改变库存容量、配方、生成器或存档身份，不新增现代整合包能力。人类审核/合并仍由人完成，不自批、不绕过保护或弱化 CI。

## 目标与决策

1. 普通右键优先使用所瞄准的可交互箱子/工作台/炉体，两种模式一致。潜行修饰右键明确绕过容器，按原放置规则放置手持方块。打开容器显示真实工位槽位；创造目录继续由独立背包入口打开。
2. 创造放置的工位必须有正式领域实体；不能只有外观方块。已存在的正式存档保持可用，不任意改写世界或扫描生成实体。
3. 统一第一方工具、剑、成长材料与新增方块的图标/持物/世界外观。先核对源分辨率、采样、缩略图路径和材质，再修真实原因；优先复用现有资产管线，保留项目自有美术语言与用户外观覆盖，不复制第三方素材。
4. 清晰度指可观察的边缘、轮廓、材质区分与界面辨识度；不以调高分辨率数字或采样参数替代实际截图。风格依据现有木材、石材、黄铜与低多边形环境统一，不引入互不相干的素材。
5. 用户选择精细像素风：工具/成长材料采用独立`:detail` ID的32×32分层材质源，保留所有原16px纹理ID/像素及旧覆盖的模型语义，所有物品图标由同一模型管线生成带透明背景的缩略图。新增可选 pixelsPerUnit 仅表达像素模型尺寸，省略仍为旧 16 单位语义；复制/导入保留密度，不能改变旧用户资产。工位/矿石沿用现有 pixel16 地形合同并重绘辨识结构。
6. 用户追加工具手持和缩略图过小的问题：工具独立放大、GUI 正交取景与槽位放大；沉淀 [物品视觉设计规范](../../docs/item-visual-design.md)，明确外部参考与项目自定阈值，验证桌面、竖屏、超宽屏及动作姿态。
7. 用户追加物品预览居中：背包、快捷栏和工位结果按实际可见轮廓对齐格子中心，两轴偏差均不超过1 CSS px；数量、快捷键与耐久独立叠加，不能挤偏图像。先在真实页面取得偏移RED，再验证桌面与窄屏GREEN。
8. 不安装新依赖；若确需依赖，一律 npmjs 公共源。生产渲染保持 WebGL2，不作性能收益声明。

Root 拥有视觉资产/材质/缩略图管线与记录、集成验收。Sol/high 创造交互 worker 拥有 Core 交互与 browser/player/inventory UI 接线及专用测试；路径互斥。Sol/xhigh 做一次独立只读审阅。按用户要求，Sol/high CI worker 在推送后接手相关失败修复，不与本地实施并发写同文件。
