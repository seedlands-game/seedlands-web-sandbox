# 资产工坊与第一方资产来源

资产工坊入口为 `asset-workbench.html`。执行 `pnpm dev` 后访问该路径；生产构建保留游戏 `index.html` 与工坊两个入口，遵循相同 base 子路径。工坊不启动世界和 Worker，不获取 Pointer Lock。

## 统一目录，分别生产

目录统一标识、类型、revision 和引用关系；用途绑定与生产方式分开。当前内置 108 项资产：覆盖 10 个非空气方块、10 种物品、人物/生物、第一人称手臂、地形面、模型材质和当前 UI/目标图片。点击模型的材质、再点击材质的贴图，可以追溯源数据。内置资源只读，贴图可复制为草稿。

| 类型               | 当前能力                                     | 共享实现                                                                      |
| ------------------ | -------------------------------------------- | ----------------------------------------------------------------------------- |
| 像素贴图           | 创建、绘制、保存、导入导出；地形贴图显式试用 | `asset-tool-sources.ts`、`terrain-assets.ts`、`model-material-definitions.ts` |
| 像素挤出模型       | 总厚度、握持点、关联贴图与手持动作           | `voxel-tool-model.ts`、`pixel-model-resource.ts`                              |
| 方块/异形方块      | 原地形网格、透明/裁切/发光预览               | `meshChunk`、`voxel-materials.ts`                                             |
| 物品及掉落模型     | 原程序化模型预览                             | `gameplay-model-assets.ts`                                                    |
| 人物、生物、手臂   | 共享构件与材质；默认方块比例                 | `actor-model-definitions.ts`、`builtin-actor-models.ts`                       |
| 材质               | 属性、贴图依赖与运行效果检视                 | 地形材质与模型材质分别适配                                                    |
| UI、目标、物品 PNG | 原图、采样与平铺检视                         | `asset-image.ts`、`preview-scene.ts`                                          |
| 外部静态 GLB       | 导入、保存、刷新预览、原文件导出、删除       | `glb-model.ts`、`glb-model-resource.ts`                                       |

像素挤出目前只绑定木斧和石镐，并检查物品元数据的不可放置条件。方块保持 Chunk Mesh；生物模型不改变规则和碰撞。玩家全身模型是同源比例参考，当前游戏只显示第一人称手臂；居民采用同一默认人形比例。已有数学动作保持，尚无骨骼动画适配。

## pixel16 源与图集规范

默认 tile 为 **16×16 像素**，并非 16 bit 色深。像素源记录命名空间 ID、revision、尺寸、调色板与像素索引；最多 32 色，索引 0 为透明。旧 32/64 方形草稿继续读写，不降采样。角色未来可使用更大的 UV 图；默认风格不限制外部 GLB 的美术方向。

13 张独立地形源和 20 张模型材质源由仓库内确定性规则生成。游戏已从旧大图切片切换到这些源；旧 `voxel-atlas.webp` 和部分旧缩略图保留历史兼容，不是新的生产源。地形通过现有 WebGL2 纹理数组上传，13 个 FaceMaterial 数值及层对应关系保持；最近邻放大，不将图集位置写入逻辑 ID。

“导出图集与索引”编译当前像素源及已应用地形快照，提供 PNG 与 JSON 两个下载链接。按 ID 排序，1 像素扩边，索引记录每个矩形的位置、尺寸与 revision。此 PNG 适用于最近邻、无 mipmap 的图集消费者；不能直接以普通全图 mipmap 替换地形纹理数组。

JSON 格式 `seedlands-texture-atlas` 包含独立 `sources`、地形 `materials`、`schemaVersion`、`contentRevision` 和 `atlas.compilerVersion`。源是编辑真相，PNG/索引可重新编译。它是纹理编译产物，不是完整模组包，也不是“导入像素包”接受的草稿 JSON 格式；当前没有一键导入整套图集、GLB 和玩法绑定的装配器。后续协议演进须区分 schema、内容和编译版本，并为不兼容版本提供迁移或明确拒绝。

## 贴图试用

1. 按用途选择“泥土”等方块，沿材质引用进入贴图，点击“复制为草稿”。
2. 绘制并保存，选择目标地形材质，点击“应用贴图到游戏”。
3. 打开新游戏标签，或重新加载已有游戏入口。游戏启动时读取已保存快照；正在运行的世界不会热切换。
4. “恢复此材质默认”只移除此目标覆盖；重新打开游戏后恢复内置源。

地形仅接受 16×16；不透明材质拒绝透明像素。草稿后续编辑不隐式改动已应用快照。水、裁切与发光仍使用既有游戏材质行为。当前模型材质可检视、复制贴图和导出，但未提供运行替换绑定。

## GLB 导入合同

使用“下载模型样例”可取得仓库程序生成的静态木箱；也可从外部工具导出自包含 GLB 2.0。导入文件最多 16 MiB，库最多 16 个模型/64 MiB，最多 256 节点和 10 万实例三角形，纹理单边最多 4096、合计最多 16 Mi 像素。

当前支持索引三角形、内嵌 PNG/JPEG、静态场景和所列受支持材质扩展。外部或 data URI、骨骼、动画、形变、稀疏访问器、压缩几何/纹理及未知必需扩展明确拒绝。保存前校验结构、范围和引用；导出保持原文件字节。预览只在外层居中归一化，原根节点变换不改写。导入不注册物品、不替换方块、不创建碰撞。

## 存储与资源所有权

- `seedlands-asset-workbench`：原生草稿，最多 128 条、导入 JSON 最多 2 MiB；库 revision 防止多标签静默覆盖。模型导出包含贴图依赖，导入生成新 ID 并重写引用。
- `seedlands-terrain-pack`：显式应用的源快照，独立 content revision 与事务冲突检查；失败不覆盖已有包。
- `seedlands-glb-assets`：独立 GLB Blob 和经过校验的元数据；事务内检查容量，原子保存。

三个库均不改世界存档。浏览器清理站点数据会移除资产，需自行导出备份。后续服务器可以接在异步存储边界，权限、同步、冲突与发布协议另行定义。

GPU 对象始终按 Application 创建，不持久化、不跨 WebGL context 复用。工坊与游戏共享模型构件、像素资源及第一人称动作，预览只组合镜头与光照。内置资源使用有界缓存；草稿、GLB 和地形预览按生命周期释放，异步加载取消时拒绝陈旧结果。不同镜头下不要求截图逐像素一致。

## 借鉴范围

参考 Minecraft Bedrock 官方的[资源包入门](https://learn.microsoft.com/en-us/minecraft/creator/documents/resourcepack?view=minecraft-bedrock-stable)与[协作 Add-On 规范](https://github.com/MicrosoftDocs/minecraft-creator/blob/main/creator/Documents/Practices/GuidelinesForBuildingCooperativeAddons.md)：独立纹理文件、资源描述与玩法分离、明确命名空间值得借鉴。Seedlands 当前使用自己的协议与纹理编译格式；这里不承诺兼容 MC 资源包，也不照搬其版本号。
