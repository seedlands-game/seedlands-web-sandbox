# 资产工坊与第一方资产来源

资产工坊入口为 `asset-workbench.html`。执行 `pnpm dev` 后访问该路径；生产构建保留游戏 `index.html` 与工坊两个入口，遵循相同 base 子路径。工坊不启动世界和 Worker，不获取 Pointer Lock。

## 管理与生产的分工

资产目录统一标识、类型、版本与引用关系；物品用途绑定保持独立。资产适配器声明其可编辑性和预览模式，不强制所有资源采用同一种生产方法。

| 类型               | 当前能力                                     | 代码入口                                         |
| ------------------ | -------------------------------------------- | ------------------------------------------------ |
| 像素贴图           | 可复制创建、绘制、保存、导入导出             | `asset-tool-sources.ts`、`asset-package.ts`      |
| 像素挤出模型       | 可调整总厚度、握持点、关联贴图，复用手持动作 | `voxel-tool-model.ts`、`pixel-model-resource.ts` |
| 当前物品 PNG       | 原图、采样与平铺检视，只读                   | `asset-image.ts`、`preview-scene.ts`             |
| 当前程序化物品模型 | 调用游戏原有表现，只读                       | `gameplay-model-assets.ts`                       |

后续艺术 3D、动画等应增加适配器。已有方块/异形方块/实体生产链不转为像素挤出链，也不改变 Chunk Mesh 所有权。

像素挤出的游戏绑定目前只有木斧和石镐，并检查物品元数据的不可放置条件。其他物品仍能进入统一目录，通过其适配器展示。原生草稿没有修改内置绑定的权限。

## 单一来源与运行资源

- `src/client/presentation/asset-catalog.ts` 保存明确的第一方资源及用途绑定；覆盖度通过权威物品注册对照测试约束，不按未知 id 猜资源。
- `asset-tool-sources.ts` 的像素源产生原生资产定义；游戏工具网格、图标与工坊读取同一来源。木斧/石镐不再读取旧 PNG，现有文件只保留历史兼容，不能作为当前编辑源。
- 纯类型、校验与生成逻辑位于 `src/client/presentation/`；浏览器编辑/预览在 `src/app/asset-workbench/`；GPU 创建由游戏和工坊共享的 `pixel-model-resource.ts` 承担。
- 工坊预览复用 `FirstPersonViewmodel` 和 `viewmodelPose`；不同镜头、光照的截图可以不同，不能因此声称运行算法不同或要求逐像素相同。
- 持久化只保存原生源数据。GPU 网格、材质、纹理和图标可重建，不保存 PlayCanvas 实例，也不跨 WebGL context 复用对象。
- 内置工具网格保留每 Application 的有限缓存；草稿网格不缓存，每次修改先创建新资源，切换后释放旧引用；异步图片加载使用请求版本拒绝陈旧结果。

## 本地保存与备份

工坊使用独立 IndexedDB `seedlands-asset-workbench`，不读写世界存档。只在事务提交后标记已保存；使用库 revision 阻止多标签静默覆盖。保存冲突可以导出备份、重新加载或另存为副本。

原生 JSON 包包括 schema 版本和资产记录，导出模型同时包含其贴图依赖。导入先校验、再创建新的 id 并重写依赖，不覆盖已有资产。图片与程序化模型当前仅为内置只读引用，不接受导入包中的任意 URL、脚本或未知类型。

本地库最多 128 条草稿，原生导入包最多 2 MiB；贴图限 16/32/64 方形画布、32 色、二值透明。删除共享贴图须先解除引用。浏览器清理站点数据会失去本地库，导出包用于备份；草稿不会自动发布进游戏。

后续服务器可接在异步存储边界，仍须另行定义权限、冲突与发布流程。当前不提供账号、同步、GLB 建模或游戏热更新。
