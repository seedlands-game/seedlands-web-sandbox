# 协作与模型路由

默认先判断确定性脚本能否完成，再选择模型和分派方式。全局 `agent-work-routing` skill 是详细规则；未安装时使用 `changes/2026-09-07-agent-routing-contracts/skill/agent-work-routing/SKILL.md` 的版本化源。它不要求每个任务使用多个 agent，也不覆盖人类直接选择的模型。先界定问题、准出、文件所有权、权限和预算；独立工作可以并行，集成按依赖顺序进行，最后由负责者闭环验收。

## 默认交接

本项目默认按“澄清需求 → 独立 worktree → 按任务独立性与总成本分派或并行 → 验收 → 可读 PR → 跟进至可交棒 → 人类审核”交接。将功能分支推送至已配置 `origin`、以目标分支为 base 创建或更新 PR 已获本用户长期授权；用户指定 `local-only`、不发 PR 或其他范围时优先。PR 摘要只写问题和结果、关键范围与验证证据，不附过程日志。

实现交付在验收后完成提交、推送、创建或更新 PR，并读回远端 SHA、source/target、URL 与当前 gate 快照后停止。CI 未完成时如实标记，不自动常驻等待或修复；后续 readiness 由用户单独发起。人类审核与合并仍由人完成，不能只看 `MERGEABLE` 字段。

| 初始路由    | 适合的工作                                 | 典型落地                                            |
| ----------- | ------------------------------------------ | --------------------------------------------------- |
| 确定性脚本  | 可机器判定的固定转换和批处理               | 一次准备、有界执行、机器验收                        |
| Astra/high  | 顶层标准、MVP 设计、模糊探索、复杂 UI 实现 | 当前任务或有界 subagent 闭环                        |
| Sol/high    | 明确的长开发                               | 单次 subagent 端到端实现、自测、修复                |
| Terra/high  | 执行验收与回归核查                         | 一次独立验收 subagent；跨请求固定职责才考虑独立任务 |
| Luna/medium | 限定只读资料提取                           | 有界提取，不开发                                    |
| Spark/xhigh | 纯文本机械扫描                             | 输入输出明确，不开发                                |

默认档位可按任务成本、能力和项目基线以明确理由调整，但不能用泛化理由绕过长开发默认 Sol 的标准；Luna 和 Spark 不开发。agent 派发前先生成并校验父子合同，使用完整交接文本；合同路径是所有权约束，不是 OS sandbox，脚本也不能硬拦截平台工具。嵌套派发继承父范围、权限与共享预算，父 agent 汇总已分配和已消耗值。

性能回归注册固定职责 `seedlands-performance-validator`，默认 `Terra/high`，通过[性能执行窗口](performance-execution.md)取得当前机器样本。该身份是可复用职责约定，不要求在本轮空闲时创建长期任务；创建独立任务仍需用户授权和工具许可。

## 长异步监控

CI、构建和其他长等待优先使用平台终态事件或已有原生 `wait`/`watch`。每个监控明确绑定任务或 run id、来源 SHA、归属、状态来源、截止时间和回报对象。主任务交出监控后结束当前活动轮次或处理独立工作，不周期性唤醒再问 worker；普通子任务的返回也不等同于跨轮次唤醒。

只读状态查询优先确定性脚本；需要判断时由 `Terra/high` 处理，纯文本机械状态归约才可选 `Luna/medium` 或 `Spark/xhigh`。心跳每次只读一次紧凑状态并低频运行，`pending` 不汇报；如果平台不能为心跳单独选模型，不能声称它免费或低价。终态、截止、取消、HEAD 变化或需要人工决定时才回报，并立即停用监控。监控不得自动重跑、修复、合并或部署；CI 失败先由 `Terra/high` 提取绑定 SHA 的最小失败证据，明确修复再交 `Sol/high`，架构或权限问题回到主任务。

任务成本记录应包含执行、上下文、协调、返工和验收；工具等待不等于模型工时，也不要为便宜模型制造更多交接。记录规模、完成情况、墙钟、各模型输入/缓存/输出 token，以及实际额度（若可得），父任务汇总整棵任务树。未知写 `unknown`。若需要 API 估算，动态核对当时的[官方模型比较页](https://developers.openai.com/api/docs/models/compare)；API 估算、credits、token 和实际账单分别记录。

大规模任务在分派或实现前按[工作量与预算规范](change-estimation.md)估算 PD、单 agent/拟议协作的关键路径、各模型 credits 与 API 成本、额度占比及 20% 缓冲。模型分工应比较包含协调与返工的总成本；价格、倍率和额度必须带当前来源。不要只比单价，也不要把多 agent 总工时当成墙钟节省。
