# 物品视觉设计规范

适用范围：第一方工具、武器、资源、工位与方块在背包、快捷栏、第一人称持握及世界中的呈现。当前美术方向为精细像素风：清楚的方块轮廓、分层材质、暖木与黄铜、冷灰石与铁。此规范约束新增资产与资产重绘，用户导入外观仍尊重其作者定义。

## 参考与本项目决策

2026-09-10 查阅以下一手资料。借鉴呈现原则，不复制纹理、模型或品牌资产；下面的尺寸百分比是 Seedlands 的验收值，不是 Minecraft 或 Vintage Story 的官方标准。

- [Minecraft 官方镐介绍](https://www.minecraft.net/en-us/article/taking-inventory-pickaxe)：官方配图中的双端镐头、长柄和材质分区构成清楚的工具轮廓。木、石、铁等级沿用可识别的同类结构，材质表达承担等级区分。
- [Minecraft hand_equipped](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/itemreference/examples/itemcomponents/minecraft_hand_equipped?view=minecraft-bedrock-stable) 明确区分工具式手持呈现；[Item Display Transforms](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/blockreference/examples/itemdisplaytransforms?view=minecraft-bedrock-stable) 分别定义第一人称、GUI、第三人称和地面变换。采用“按显示场景分别定标”的原则，不能为了放大背包而改变世界尺寸。
- [Vintage Story 第一人称重做](https://www.vintagestory.at/blog.html/news/v1190-pre1-dejank-redux-r367/) 及其官方弓持握图展示了手臂、握持点与动作的整体构图；[官方渲染目标 API](https://apidocs.vintagestory.at/api/Vintagestory.API.Client.EnumItemRenderTarget.html) 也区分 GUI 与第一人称手持。弓在使用姿态中可显著进入画面，这不能直接作为镐/剑待机尺寸模板。

## 轮廓、像素与材质

工具和成长资源采用 32×32 原生像素画布，像素模型显式使用 32 pixelsPerUnit，厚度默认 4 像素。原16px内置纹理ID及其像素完整保留，新默认模型引用独立的`:detail`纹理ID。旧项目只覆盖旧纹理时使用原握持点和厚度；显式模型或新detail纹理覆盖优先，不原地改写项目。旧资产省略密度仍按 16 pixelsPerUnit 解释；画布升级不能使世界中的模型自动增大一倍。工位与矿石保持既有 16×16 地形纹理合同。

先画轮廓再画材质：镐的两端、斧的单侧刃、剑的尖端与护手必须在小图中可区分。工具握持点位于柄下段，不落在刃部；刀刃、连接箍、握柄、柄尾分区明确。不能用零散噪点代替结构。

每种材质至少包含暗部、主体、亮部三个色阶。木材用纵向纹理与暖色明暗，石材用冷灰断面，铁用较窄的亮边与大块平面，黄铜只用于连接件和装饰。像素边缘使用最近邻采样，不给源像素图加模糊或柔边；图标允许模型渲染的轮廓抗锯齿，但保持内部像素层次。

工位采用可辨识功能面：工作台的镶嵌台面与侧面支撑，箱子的木板、束带与锁扣，炉体的砖缝、炉口与炉火。界面图标与持物必须来自实际模型，避免图标和放置后的物体不一致。

## 缩略图与槽位

| 项目                | 标准                                                                                                                                  |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 输出                | 512×512 透明 PNG，同一模型渲染管线；禁止不透明黑底                                                                                    |
| 投影                | GUI 使用正交投影，模型 yaw 25°、pitch 12°；工具额外倾斜35°利用对角线，按实际顶点的投影范围居中                                        |
| 轮廓填充率          | 非透明轮廓最长边目标 88% 画布；自动验收 83%–94%，四边不得裁切                                                                         |
| 测量口径            | alpha ≥128 的像素包围盒最长边 / 画布边长，不能只测 img 标签尺寸                                                                       |
| 背包槽位            | 桌面 58px 高的槽位用 46px 图像盒；窄屏 48px 槽位用 38px 图像盒                                                                        |
| 合成结果 / 创造目录 | 结果槽高 72px，用 56px 图像盒；创造目录图像盒 46px                                                                                    |
| 居中                | 按可见轮廓包围盒中心对齐格子几何中心；两轴偏差均≤1 CSS px。图像层独立于按钮内边距，快捷栏四边留白对称，数量/快捷键/耐久不参与图像布局 |
| 信息层              | 数量固定右下，快捷键左上，耐久条底部；不得用缩小工具来给文本让出整块空白                                                              |

验收既检查源 PNG 轮廓，也在实际背包、快捷栏、创造目录与工位结果中查看最终尺寸。细长剑按最长边定标，不强行拉宽；不同材质的同类工具保持相同轮廓尺寸。

## 第一人称持握

工具采用独立于普通物品的呈现缩放：当前工具 0.95、普通物品 0.55；这是显示层参数，不改变掉落物、碰撞体、交互距离、命中规则或权威动作时长。资产工作台的像素工具持握预览使用同样的工具缩放。

握持点固定在右下手部，工具从柄向上、向内延伸，手臂尺寸不随工具放大。默认 72° FOV、16:9 待机时，镐/斧/剑的可见高度目标为视口高度约 30%–45%；这是人工构图验收目标，不能以 scale 常量或单测代替真实帧。

待机准星周围宽 20%、高 20% 的中心区域保持清楚；工具头和剑尖不得被顶部或侧边裁切。手臂/柄尾可自然出下边界，挥动期间可短暂进入中心，但不能长期遮挡目标。不得通过禁用动作、改变权威动作阶段或缩小整个手臂来满足裁切检查。

新增工具至少复查 1280×720、720×960、1920×810 的待机画面；另外逐帧检查举起、挥击与恢复。当前竖屏工具以0.79倍显示缩放、向直立方向旋转16°，握持锚点向右调整，给准星让出空间；这些变换不修改资产的物理密度。工具头过小优先检查模型留白、握持点和相机投影；材质弱先检查明暗与厚度，不以无限加大模型代替。

## 制作与交付

1. 更新当前 change spec：列出物品、受影响显示场景、可观察失败和验收帧。
2. 修改第一方像素源或地形源，保持稳定资产 ID、绑定与用户覆盖兼容。
3. 使用仓库现有缩略图脚本从本地渲染器重建全部受影响图标。
4. 运行密度/导入导出/网格表面与三角形预算测试，检查实际 PNG 的透明度、填充率和裁切。
5. 在真实 Browser 游戏复查库存与持握；保存同场景前后图，并说明投影或布局是否变化。自动测试不代替最终美术验收。
6. 执行基础静态检查和构建、独立审阅，关闭临时验证服务；记录最新代码和 CI 的对应关系。

本规范的首次实施及证据见 [创造容器与视觉一致性 change](../changes/2026-09-10-creative-containers-visual-cohesion/spec.md)。后续资产偏离以上标准时，须在对应 change 说明原因和实际验收结果。
