# NPC 行为、玩法能力与认知

本页描述 [NPC 可组合基线 change](../changes/2026-09-10-npc-composable-baseline/spec.md) 的分层合同。准出状态、实际用例与尚未验证的范围以该 change 的执行记录为准，不把架构说明当作运行验收。

## 谁拥有状态

| 层              | 所有者与职责                                                                | 不拥有的权限                                  |
| --------------- | --------------------------------------------------------------------------- | --------------------------------------------- |
| 世界与 ECS      | game-core 每世界实体 owner 持有身体、身份、生命、需求、库存、控制和行为状态 | 不依赖模型、数据库或浏览器                    |
| 通用行为执行    | core 中的行为定义校验、注册表与标准执行模块按逻辑时间推进                   | 不另建 NPC 库存，不直接改体素，不替玩法作授权 |
| 玩法机制模块    | 注册能力描述、参数合同、持续执行生命周期；调用已注册领域操作                | 不能从自己的权限声明取得宿主授权              |
| Pack / Playbook | 打包机制、内容和行为配方；选择并配置装配                                    | 不导入 NPC、ECS 和 GameServer 私有实现        |
| Web             | 操控、显示、Worker 传输和当前角色绑定；将局部观察发给认知服务               | 不维护第二套世界真值                          |
| Agent Server    | 按世界、timeline、Actor 隔离认知工作区；提出行为树、说话与记忆              | 不获全局开发 Harness、任意状态写入或身体 tick |

行为树不是放在模型服务里的循环脚本。行为状态进入 ECS 组件系统，执行器位于纯逻辑 core；默认主世界通过标准模块启用它。没有该模块的 Playbook 仍可运行自己的玩法，不应暗中创建默认 NPC。

身体的食物、消耗和合成与玩家共用领域操作、当前物品定义和规则。行为只根据受限观察决定下一步；成功必须来自执行器/领域回执，模型文本不构成成功。

## 新玩法如何暴露给 NPC

作者通过 `@seedlands/game-core/mod-api` 注册带命名空间的能力，而不是给 NPC 内核加一个玩法分支。能力包括条件和技能：描述与有界参数供编排，回调供实际执行，持续技能还要声明状态版本、大小上限及 start / continue / cancel 语义。

每世界装配后目录冻结。世界级目录用于作者和出生配方；绑定 NPC 的目录由当前 Actor 身份、生命及行为控制资格过滤。目录并非权限票据：每次操作仍检查原始 Actor、epoch/lifetime、provider 版本、目标引用、宿主许可和当前规则。条件返回 false 与未准入能力是不同事实。

扩展需要独立的宿主准入：`host-admissions.json` 固定 Pack 的 id、version、完整产物摘要和允许权限。Pack manifest 只请求能力，不能自授予权限；没有准入、摘要不符或多余准入均拒绝。它是可信产品部署配置，不是任意外部 JavaScript 的安全沙箱。

[营地加工样例](../changes/2026-09-10-npc-composable-baseline/examples/camp-work.ts) 独立构建为 ESM Pack，提供一个材料条件和一个分阶段技能，再通过公开行为配方组合既有生活树。完成加工走正常库存合成操作。新增类似玩法只需实现公共合同和配方；系统不会自动理解任意未声明的机制，也不承诺无需作者描述即可理解所有 AI 生成代码。

## 存档与恢复

世界存档持有可恢复的身体和行为状态：稳定 Actor 身份、定义/行为修订、当前节点与技能状态、provider/state 版本和已有动作关联。物理运行引用在恢复后绑定新 epoch，旧消息不得重新控制新身体。继续、取消、失败和终态需要分别验证，尤其不能在恢复时重复提交已经生效的消耗或产出。

活体行为的唯一持久状态在 `entityStore.actors[].character`。身体移除后，`simulation.characterTombstones` 最多保留128条已故角色的身份、人格、行为和事件记录，不包含另一份库存、饥饿或身体；恢复不能凭墓碑重新生成活体。旧 `simulation.characters` 只作为旧存档迁移输入。

Pack/module 组合身份继续属于存档兼容合同。已有 main 存档和 Agent 旧存档经显式迁移，不忽略摘要差异、不丢弃库存槽位来伪装兼容。当前 schema 和支持的精确旧身份以 codec 与迁移测试为准。

Agent 的长期记忆在 PostgreSQL；它不代替世界存档。浏览器应用 checkpoint 将世界快照与 cognition timeline 配对，回档时选择对应认知分支。旧 timeline 的响应不能应用到新世界。普通世界 checkpoint 与包含认知的应用 checkpoint 是不同层级，不能仅导出世界后声称记忆也恢复了。

应用清单V2额外校验同一次捕获的pairHash及认知来源world/timeline，拒绝旧V1应用清单而不猜测配对；core世界V1–V4迁移另行维持。pairHash不是签名，也不是跨世界与PG的分布式事务。PG导入在写入前重放文档尺寸、完整journal/window链及resident运行时codec检查；未知调度版本不能静默变成新角色的默认时钟。

## 断开模型也能生活

已安装的合法生活树按模拟时钟持续执行：觅食、进食、避险、白天活动和夜晚回家不依赖每 tick 模型请求。认知服务慢、断开或报错时，身体仍执行已接受的树；失败对用户可见，不能偷偷改用另一模型或宣称新的计划已生效。

模型响应有1MiB实际字节上限，单消息最多8个工具调用；单逻辑轮最多8次模型请求、8个工具和3次改树提案。工具整批在执行前预检剩余预算，超额不提交该批次的世界副作用。已成功的先前动作保留其回执，不假装失败会回滚历史。暂停时断线后重连，以当前世界暂停状态恢复计时，不沿用过时的暂停标志。

1MiB是传输最大值；保留原始审计字段后的最终LangChain消息还需满足512KiB journal预算（预留1KiB编码余量），超出会在网关适配阶段拒绝。服务重连会重新检查当前准入与durable context状态，旧会话的临时blocked标志不是永久禁用；死亡、无模型或尚未修复的中断journal仍拒绝调度。

三角色验收分开记录：有限资源与昼夜循环的确定性世界证据、三个独立认知通道的协议证据、真实模型对话改变行为并落到世界的证据，以及画面/人的体验判断。“有三个人形模型”或“模型回复了三句话”都不足以证明具有活人感。

## 本地运行边界

运行命令以根 `package.json` 为准：`pnpm dev` 启动 Web，`pnpm agent:dev` 构建并启动独立 Node 认知服务。Agent Server 不是已归档的 Node Dedicated 世界宿主。

Agent 需要 `SEEDLANDS_COGNITION_DATABASE_URL`。PostgreSQL 可以是现有实例；本地验收使用隔离 Docker 容器并在结束后清理，不能删除用户的数据库卷。基础世界和无模型生活树不要求数据库。

模型接入使用 loopback 网关 URL 与网关令牌两个成对配置项：`SEEDLANDS_MODEL_GATEWAY_URL` / `SEEDLANDS_MODEL_GATEWAY_TOKEN`。上游 provider key 留在网关侧，不传到浏览器。网关 Docker 启动、双模型映射、并发/队列上限见 [网关说明](../scripts/model-gateway/README.md)。没有网关时认知服务明确报告缺失，不影响已有本地行为树。

Agent 的 WebSocket 端口默认 8787，允许的浏览器 origin 默认是 localhost/127.0.0.1 的 5173。启动回执提供一次本地会话的连接口令；只交付给本机测试者，不提交到源码、证据或 PR。`SEEDLANDS_ALLOWED_ORIGINS` 可明确配置测试 origin，不能为连接方便改成任意来源。
